# 红黑树（概述、插入、删除）

> 对应课程第 34~36 期。红黑树是工程中最常用的自平衡二叉搜索树：C++ `std::map`/`std::set`、Java `TreeMap` 底层都是它。相比 AVL 树，红黑树放宽了平衡条件，插入/删除需要的旋转次数更少，综合性能更稳定。

## 一、基本概念与术语表

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 红结点 / 黑结点 | red / black node | 每个结点被着成红色或黑色（性质约束二者的分布） |
| 哨兵结点 | sentinel / `T.nil` | 代替所有 `NULL` 的统一叶结点，本身黑色，简化边界判断 |
| 黑高 | black-height, `bh(x)` | 从 `x` 出发（不含 `x` 本身）到其任一后代叶结点路径上的**黑结点数** |
| 双黑 | doubly black | 删除修复中的记号：表示"这个位置多欠一个黑色"，需通过修复消除 |
| 叔结点 | uncle | 插入修复时，新结点的父结点的兄弟结点，其颜色决定修复走哪种情形 |
| 左旋 / 右旋 | left / right rotation | 围绕某条边局部换位，保持 BST 性质不变的结构调整操作 |

## 二、核心性质与定理

### 1. 五条性质（缺一不可）

1. **每个结点非红即黑**。
2. **根结点是黑色**。
3. **每个叶结点（哨兵 `NIL`）是黑色**。
4. **红结点的两个孩子必是黑色** ⇒ 换个说法：**任何路径上不存在连续两个红结点**。
5. **从任一结点到其每个后代叶结点的所有路径包含相同数目的黑结点**（这就是黑高处处相等的含义）。

### 2. 关键定理：树高上界

**定理**：含 `n` 个内部结点的红黑树，高度 `h ≤ 2·log₂(n+1)`。

**推导**（两步走）：

- **第一步**：以 `x` 为根的子树至少包含 `2^{bh(x)} - 1` 个内部结点。
  归纳法：`x` 为叶时 `bh = 0`，对应 `2^0 - 1 = 0` 个内部结点，成立。`x` 有孩子时，两个孩子的黑高要么是 `bh(x)`（孩子为红），要么是 `bh(x) - 1`（孩子为黑），于是每个孩子子树至少有 `2^{bh(x)-1} - 1` 个结点，合计 `2·(2^{bh(x)-1} - 1) + 1 = 2^{bh(x)} - 1`。
- **第二步**：设从根到叶的最长路径长为 `h`。由性质 4，路径上红结点不超过黑结点数，故黑结点数 ≥ `h/2`，即 `bh(root) ≥ h/2`。
  结合第一步取 `x = root`：`n ≥ 2^{bh(root)} - 1 ≥ 2^{h/2} - 1`，解出 `h ≤ 2·log₂(n+1)`。

**结论**：查找、插入、删除都是 `O(log n)`。最短路径全黑、最长路径红黑相间，恰好印证"最长 ≤ 2×最短"。

### 3. 与 AVL 树的对比

| 维度 | AVL 树 | 红黑树 |
| --- | --- | --- |
| 平衡标准 | 每个结点左右子树高度差 ≤ 1 | 黑高相等 + 无连续红结点 |
| 查找 | 略快（更严格平衡） | 稍慢（最高约 2 倍） |
| 插入旋转 | 最多 1 次（单/双旋） | 最多 2 次 |
| 删除旋转 | O(log n) 次可能 | 最多 3 次 |
| 适用场景 | 读多写少 | 增删查都频繁的通用场景（map/set） |

## 三、存储结构

采用**带哨兵**的三叉链表：所有空指针统一指向黑色哨兵 `nil`，使插入/删除修复无需特判空指针。

```cpp
enum Color { RED, BLACK };

struct Node {
    int   key;
    Color color;               // 红 or 黑
    Node *left, *right, *parent;
    Node(int k, Color c)
        : key(k), color(c), left(nullptr), right(nullptr), parent(nullptr) {}
};

class RBTree {
    Node* nil;   // 黑色哨兵，代替所有 NULL
    Node* root;  // 根结点（根的 parent 也指向 nil）
public:
    RBTree() {
        nil   = new Node(0, BLACK);       // 哨兵恒为黑（性质 3）
        nil->left = nil->right = nil->parent = nil;
        root  = nil;
    }
    // ...
};
```

对比纯递归写法（不带 parent、不带哨兵）：实现删除修复时递归写法情形繁多、极易出错；CLRS 的哨兵 + 三叉链写法是面试与教材的通用范式，建议掌握。

## 四、核心操作实现思路

### 1. 旋转（所有结构调整的基石）

左旋 `x`：`x` 的右孩子 `y` 顶替 `x`，`x` 变为 `y` 的左孩子；`y` 原左子树转给 `x` 作右子树。右旋对称。旋转**只改指针不改颜色**，且中序序列不变（BST 性质保持）。

### 2. 插入（先按 BST 插入染红，再向上修复）

- 新结点**染红**插入（染黑会违反性质 5，染红最多违反性质 2/4，好修）。
- 若父结点也是红（出现连续红），按**叔结点颜色**分三种情形修复（`z` 为当前结点，循环处理 `z = z->parent->parent` 即祖父，把 `z` 上移）：

| 情形 | 条件 | 处理 | 结果 |
| --- | --- | --- | --- |
| 1 | 叔结点为**红** | 父、叔染黑，祖父染红，`z` 上移到祖父 | 矛盾上移两层，循环继续 |
| 2 | 叔为黑且 `z` 是**内侧**孩子（如父为左孩子、`z` 是右孩子） | 对父结点左旋转化为情形 3 | 变成外侧结构 |
| 3 | 叔为黑且 `z` 是**外侧**孩子 | 父染黑、祖父染红，对祖父旋转 | 局部消掉连续红，结束 |

- 循环结束后强制 `root->color = BLACK`（覆盖情形 1 一路染到根的情况）。插入**最多 2 次旋转**（情形 2 → 情形 3 各一次）。

### 3. 删除（BST 删除 + 修复"黑色缺失"）

- 先按普通 BST 删除：叶/单孩直接摘除（transplant 接上），双孩找**后继** `y` 顶替，实际删除的是后继。
- 记录"被移除的结点颜色"：若删除的是**红结点**，黑高不变，直接结束；若删除的是**黑结点**，该路径少了一个黑——把接替位置 `x` 视为**双黑**，进入修复循环（`w` 为 `x` 的兄弟）：

| 情形 | 条件 | 处理 | 作用 |
| --- | --- | --- | --- |
| 1 | 兄弟 `w` 为**红** | `w` 染黑、父染红，朝 `x` 方向对父旋转 | 换出一个黑兄弟，转入情形 2/3/4 |
| 2 | `w` 为黑且两个孩子全黑 | `w` 染红，`x` 上移到父（父独自扛双黑） | 黑色缺失上移一层；若父原为红则染黑终止 |
| 3 | `w` 为黑，靠近 `x` 的孩子红、远离的孩子黑 | 对 `w` 旋转化成情形 4 | 凑齐"外孩红"结构 |
| 4 | `w` 为黑，**远离 `x` 的孩子为红** | 按 `w` 染父色、父染黑、`w` 的远孩染黑，朝 `x` 对父旋转 | 一步补上缺失的黑色，结束 |

- 删除**最多 3 次旋转**（情形 1、3、4 各可能一次）。

### 4. 与练习题答案相关的验证手段

代码里实现了 `validate()`：递归检查性质 4（无连续红）、性质 5（左右子树黑高一致）并返回黑高，插入/删除后立即调用，保证每步操作后树仍是合法红黑树。

## 五、复杂度小结

| 操作 | 时间 | 旋转次数 | 说明 |
| --- | --- | --- | --- |
| 查找 | O(log n) | — | 高度 ≤ 2·log₂(n+1) |
| 插入 | O(log n) | ≤ 2 | 情形 1 只变色不旋转 |
| 删除 | O(log n) | ≤ 3 | 情形 2 只变色不旋转 |
| 中序遍历 | O(n) | — | 输出即有序序列 |
| 空间 | O(n) | — | 每结点多 1 字节颜色位 + parent 指针 |

## 六、常见易错点

1. **新结点染红而不是染黑**：染黑立刻破坏性质 5，所有路径都短一个黑，没法局部修复。
2. **删除时记错"被删颜色"**：双孩情形实际摘除的是**后继结点**，要记录的是后继原来的颜色，不是被删结点的颜色。
3. **transplant 忘记更新哨兵的 parent**：`v->parent = u->parent` 即使 `v == nil` 也要执行，否则删除修复里 `x->parent` 会指向悬空结点——这是 CLRS 哨兵写法最隐蔽的坑。
4. **修复循环的镜像情形写反**：父为右孩子时，左/右旋与"内侧/外侧"判断全部镜像，建议写成左右对称的两段或用统一方向变量。
5. **叔结点"为黑"包括叔结点是哨兵**：哨兵是黑的，情形 2/3/4 同样适用，不能只判断"存在且为黑"。
6. **情形 1 只变色不旋转**：循环会沿祖父继续向上；而情形 4 处理完必须**跳出循环**，不能继续上移。
7. **忘写最后的 `root->color = BLACK`**：插入情形 1 可能把根染红，漏掉就违反性质 2。
8. **黑高定义不含自身**：`bh(x)` 从 `x` 的孩子开始数，叶哨兵黑高为 0，树的黑高通常指 `bh(root)`。
9. **验证性质时漏掉 BST 有序性**：红黑性质全对但中序无序的树也存在（旋转方向写反就会造出这种"合法但不合格"的树），完整校验应包含中序有序检查。
