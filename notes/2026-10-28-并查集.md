# 2026-10-28 并查集（QuickFind / QuickUnion）

> 对应课程第 17~18 期。并查集（Union-Find，也叫 Disjoint Set Union）解决的是这样一类问题：
> 有 n 个元素，不断告诉你"某两个元素属于同一类"，随时要回答"某两个元素是不是同一类"。
> 它只有两个动作——**合并两个集合（union）**、**查某个元素属于哪个集合（find）**，
> 却能在 O(α(n))（几乎是常数）的时间里完成，是 Kruskal 最小生成树、连通分量统计、
> 朋友圈/亲戚问题、判环等算法的地基。

## 1. 基本概念与术语表

| 术语 | 含义 |
| --- | --- |
| 并查集（Union-Find / DSU） | 维护一族**互不相交**的动态集合，支持合并与查询归属的数据结构 |
| 代表元（representative / 根） | 每个集合挑一个元素当"身份证"，同集合内所有元素 find 到同一个代表元 |
| 等价关系 | 满足自反、对称、传递的关系；"属于同一类"就是等价关系，其划分出的类叫**等价类** |
| 双亲表示法 | 用数组 `parent[x]` 记录 x 的父结点，森林中每棵树的根满足 `parent[r] == r` |
| QuickFind | 数组里直接存"集合编号"的实现，find O(1)、合并 O(n) |
| QuickUnion | 数组里存"父结点下标"的实现，合并只需挂根，但树可能退化成链 |
| 按大小合并（union by size） | 合并时把**元素少**的树挂到**元素多**的树根下，保证树高 ≤ log₂n |
| 按秩合并（union by rank） | 同上的变体，用"树高上界 rank"代替"元素个数 size"作比较依据 |
| 路径压缩（path compression） | find 时顺手把路径上所有结点直接连到根，把树压扁 |
| 连通分量（connected component） | 无向图中互相可达的点构成的极大点集，可用并查集动态维护 |
| 反阿克曼函数 α(n) | 增长极慢的函数，α(n) ≤ 4 对所有现实规模都成立 |

**为什么需要它？** 如果用二维数组或邻接矩阵维护"谁和谁同类"，合并要改 O(n²) 个格子；
用 BFS/DFS 每次查询都要重跑一遍图，O(n+m)。并查集把"合并"和"查询"都压到了近常数，
而且支持**边加边问**（在线）。

## 2. 核心性质与定理

### 定理 1：QuickFind 的代价是"查得快、合得慢"

`unite(a,b)` 要把编号为 `rb` 的所有元素逐个改成 `ra`，必须扫描整个数组，故单次合并 O(n)。
做 n-1 次合并的总代价是 Θ(n²)。n = 10⁵ 时就是 10¹⁰ 次赋值，必然超时。

### 定理 2：朴素 QuickUnion 会退化成一条链

`unite(a,b)` 只做 `parent[root(a)] = root(b)`，合并方向完全随意。若依次执行
`unite(0,1), unite(1,2), …, unite(n-2,n-1)`，会得到 `0→1→2→…→n-1` 一条链，
树高 n-1，`find(0)` 要走 n-1 步。第 i 次合并的 find 要走 i 步，总代价 Θ(n²)。

配套代码实测（n = 1000）：**树深 999，`find(0)` 走 999 步**。

### 定理 3：按大小合并后，树高不超过 ⌊log₂n⌋

**证明（对"结点被挂走的次数"归纳）**：
设合并时两棵树大小为 s₁ ≤ s₂，把 s₁ 挂到 s₂ 下。此时：

1. s₁ 中每个结点的深度都 +1（这是它们唯一一次"变深"的机会）；
2. 新树大小 s₁ + s₂ ≥ 2s₁，即**被挂走的结点所在集合的大小至少翻倍**。

一个结点所在集合的大小从 1 开始，最多翻倍 ⌊log₂n⌋ 次就到 n，所以它最多被挂 ⌊log₂n⌋ 次，
深度也就 ≤ ⌊log₂n⌋。∎

配套代码用**最坏顺序**（每次都是同样大的两棵树合并）验证：n = 1024 时实测树深正好 **10 = log₂1024**。

### 定理 4：两种优化合用的均摊复杂度是 O(α(n))

- 只用路径压缩：均摊 O(log n)；
- 只用按秩/按大小合并：单次最坏 O(log n)；
- **两者合用**：任意 m 次操作的总代价 O(m·α(n))，Tarjan（1975）证明这是该问题在
  只允许这两种操作时的**下界**（不能更优）。α(n) ≤ 4，工程上直接当常数。

### 性质 5：并查集不支持"分裂"

只能合并，不能把一个集合拆开，也不支持删除单个元素。需要撤销时用**可撤销并查集**
（按秩合并但**不做**路径压缩，用栈记录每次改动，按时间倒序回滚）；需要删点时用
"给每个点建虚拟副本"（离线技巧）。

## 3. 存储结构

### 3.1 顺序存储（双亲表示法，主流）

```cpp
// 并查集的全部数据就是两个数组
struct DSU {
    int n;                 // 元素个数（下标 0..n-1）
    std::vector<int> parent;  // parent[x] = x 的父结点；根满足 parent[r] == r
    std::vector<int> size;    // 仅当 x 是根时有意义：该集合的元素个数
    int cnt;               // 当前连通分量（集合）个数
};
// 例：parent = {0,0,0,0,4,5,5,7,8,9}
//     => 0,1,2,3 同属一个集合（根 0）；5,6 同属一个集合（根 5）；4、7、8、9 各自独立
```

为什么不需要存"孩子"？因为并查集**只往上找根**，从不往下遍历，所以只要父指针就够了。
这种"只存父不存子"的表示法就叫双亲表示法（与第 15 期树的"孩子表示法"正相反）。

### 3.2 链式存储（QuickFind 的链表版，考试会考）

```cpp
// 用带尾指针的单链表表示一个集合：合并时把小表整体接到大表尾部
struct Node {
    int data;      // 元素值
    Node* next;    // 同集合的下一个元素
    Node* rep;     // 直接指向本集合的代表元结点（关键：让 find 变成 O(1)）
};
struct SetList {
    Node* head;    // 表头（= 代表元）
    Node* tail;    // 表尾，用于 O(1) 接链
    int   size;    // 元素个数
};
```

### 3.3 两种存储对比

| 项目 | 顺序（双亲数组） | 链式（带尾指针 + rep 指针） |
| --- | --- | --- |
| find 代表元 | 沿父指针上溯，O(α(n)) | 直接读 `node->rep`，**O(1)** |
| union | 根挂根 + 更新 size，O(α(n)) | 小表接到大表尾部，改小表全部 rep，O(min(s₁,s₂)) |
| 枚举某集合全部元素 | **要扫全表 O(n)**，做不到按集合遍历 | **O(该集合大小)**，天然可遍历 |
| 空间 | 2n 个 int | 每结点 2 指针 + 数据，约 3 倍 |
| 实现难度 | 极简，20 行 | 指针操作多，易错 |
| 实际使用 | 竞赛/工程默认 | 教材讲"等价类"时用，或需要遍历集合成员时 |

结论：**只判连通、只合并 → 用双亲数组**；**需要"把这个集合的人全列出来" → 用链表版**。

## 4. 核心操作的实现思路

### 4.1 初始化

```cpp
for (int i = 0; i < n; ++i) { parent[i] = i; size[i] = 1; }
cnt = n;   // 初始 n 个元素各自成一个集合
```

### 4.2 find：沿父指针找根

```cpp
// 迭代两趟版：第一趟找根，第二趟压平路径（推荐，不怕深链爆栈）
int find(int x) {
    int r = x;
    while (parent[r] != r) r = parent[r];      // 第一趟：走到根
    while (parent[x] != r) {                   // 第二趟：把路上每个点直接连根
        int next = parent[x];
        parent[x] = r;
        x = next;
    }
    return r;
}
```

递归版更短（`return parent[x] == x ? x : parent[x] = find(parent[x]);`），
但链长 10⁶ 时递归深度就是 10⁶，会栈溢出——**工程代码用迭代版**。

### 4.3 union：根挂根 + 按大小

```cpp
bool unite(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;          // 已同集合：可用于判环
    if (size[ra] < size[rb]) std::swap(ra, rb);  // 保证 ra 是大树的根
    parent[rb] = ra;                     // 小树挂大树
    size[ra] += size[rb];                // 维护大小（只维护在根上）
    --cnt;                               // 分量数减一
    return true;
}
```

`unite` 返回 bool 的用法很关键：返回 false 就说明这两个点**本来就连通**，
所以再加这条边就会成环——Kruskal 判环、无向图判环全靠这个返回值。

### 4.4 三个常用派生操作

| 需求 | 写法 |
| --- | --- |
| 是否连通 | `find(a) == find(b)` |
| 连通分量个数 | 维护 `cnt`，每次成功合并 `--cnt`（比事后扫一遍 O(n) 更快） |
| 集合大小 | `size[find(x)]`（注意先 find 再取，非根位置的 size 是过期值） |

## 5. 复杂度小结

| 实现 | find | union | 空间 | n 次操作总代价 |
| --- | --- | --- | --- | --- |
| QuickFind | **O(1)** | O(n) | O(n) | Θ(n²) |
| QuickUnion（朴素） | O(n) 最坏 | O(n) 最坏 | O(n) | Θ(n²) |
| QuickUnion + 按大小合并 | O(log n) | O(log n) | O(n) | O(n log n) |
| QuickUnion + 路径压缩 | 均摊 O(log n) | 均摊 O(log n) | O(n) | O(n log n) |
| **两者合用（推荐）** | **均摊 O(α(n))** | **均摊 O(α(n))** | O(n) | **O(n·α(n)) ≈ O(n)** |

实测数据（配套代码）：

| 实验 | 规模 | 结果 |
| --- | --- | --- |
| 朴素 QuickUnion 顺序建链 | n = 1000 | 树深 999，`find(0)` 走 999 步 |
| 同一条链做一次路径压缩 | n = 1000 | 首次 999 步，**之后树深 1**，第二次只走 1 步 |
| 按大小合并 + 最坏合并顺序 | n = 1024 | 树深 **10 = log₂1024** |

## 6. 常见易错点

1. **忘记初始化 `parent[i] = i`**。`std::vector<int> p(n)` 默认全是 0，
   结果所有点都指向 0，一开始就"全体连通"，答案全错。这是最高频的 bug。
2. **把结点挂到结点，而不是把根挂到根**：写成 `parent[a] = b` 就错了，
   正确是 `parent[find(a)] = find(b)`。前者会让树断裂、甚至让 find 陷入环状死循环。
3. **漏判同根**：`unite` 里不先判 `ra == rb`，会让 `cnt` 多减（分量数偏小甚至为负），
   还会让"判环"永远返回成功。
4. **`cnt` 维护位置放错**：`cnt--` 必须写在"确认两根本不同"的分支里，不能放在函数入口。
5. **递归 find 爆栈**：n 很大且链很深时递归版直接崩，写迭代两趟版。
6. **路径压缩只写了一趟**：只找到根却不改 `parent`，等于没压缩，白跑一遍。
7. **size 只在根上有效**：`size[x]` 对非根结点是过期值，必须 `size[find(x)]`。
8. **混淆 size 与 rank**：size 是元素个数，rank 是树高上界。按秩合并同样能保证
   log 上界，但两者不能塞进同一个数组混用。
9. **下标从 1 开始时数组开小了**：`parent[n]` 应开 `n+1`，否则 `parent[n]` 越界。
10. **路径压缩后不能撤销**：要支持撤销（如回滚莫队、离线分治）时必须**去掉**路径压缩，
    只保留按秩合并，并记录每次 `parent` 的改动。
11. **有向图判环不能用并查集**：并查集判的是"无向边是否构成环"，有向图要用拓扑排序
    或 DFS 三色标记。
12. **Kruskal 里丢掉 unite 的返回值**：那是判环的唯一依据，丢了就等于没判。

## 7. 练习题（答案在配套代码 code/2026-10-28-union_find.cpp 中运行验证）

1. 取 n = 10，依次执行 `unite(0,1)`、`unite(2,3)`、`unite(0,3)`、`unite(5,6)`。
   分别写出 QuickFind 的 `id` 数组和 QuickUnion 的"每个点的根"，说明为什么两者
   结构不同、但任意两点的连通性判断结果一定相同。
2. 用朴素 QuickUnion 在 n = 1000 上依次合并 `0-1, 1-2, …, 998-999`，测出树深和
   `find(0)` 的步数；然后对同一个结构调用带路径压缩的 find，比较第一次与第二次的步数，
   并解释为什么"第一次仍然很贵，之后却几乎免费"。
3. 构造"每次都是同样大小的两棵树合并"的最坏顺序，在 n = 1024 上实测树深，
   验证它等于 log₂n。再换成 n = 1000（非 2 的幂），预测并验证树深是多少。
4. 8 个学生、5 对朋友关系 `(0,1)(1,2)(3,4)(5,6)(6,7)`，用并查集求：
   ① 有几个朋友圈；② 0 和 2 是否同圈；③ 2 所在圈子的人数。
   再思考：若初始 n 个点、最终得到 c 个分量，一共"有效合并"了多少次？（用 n、c 表示）
5. 判断题并说明理由：
   (a) QuickFind 的 find 是 O(1)，所以它总比 QuickUnion 好。
   (b) 按大小合并后，任何结点的查找代价都不超过 log₂n + 1。
   (c) 用了路径压缩之后，单次 find 的复杂度一定降到 O(1)。
