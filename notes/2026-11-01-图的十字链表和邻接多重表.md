# 图的十字链表和邻接多重表

> 对应课程第 23 期。前置知识：图的邻接矩阵 / 邻接表（见 [2026-10-21-图](2026-10-21-图.md)）。
> 配套代码：[2026-11-01-orthogonal_multilist.cpp](../code/2026-11-01-orthogonal_multilist.cpp)

邻接表解决了"稀疏图存不下 n² 矩阵"的问题，但留下两个麻烦：

- **求入度难**：邻接表只存出边，要求某个顶点的入度必须把全表扫一遍，O(n+e)。
- **无向图每条边存两份**：e 条边要 2e 个边结点；删除一条边还得在两处分别找前驱，改不好就出现"两份副本不一致"。

十字链表和邻接多重表就是针对这两个问题各自给出的链式存储方案：

| | 面向 | 解决的核心问题 |
| --- | --- | --- |
| 十字链表（orthogonal list） | **有向图** | 一条弧同时挂在出边链与入边链上，入度 O(入度) 求得 |
| 邻接多重表（adjacency multilist） | **无向图** | 一条边只存一个结点，两个端点共享 |

---

## 一、基本概念与术语表

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 弧 | arc | 有向边，记作 `<u,v>`，u 是弧尾、v 是弧头 |
| 弧尾 | tail | 有向边的起点 |
| 弧头 | head | 有向边的终点 |
| 出边表 | out-edge list | 所有以顶点 v 为**弧尾**的弧组成的单链表 |
| 入边表 | in-edge list | 所有以顶点 v 为**弧头**的弧组成的单链表 |
| 十字链表 | orthogonal list | 出边表与入边表**共用同一批弧结点**的链式存储，只用于有向图 |
| `firstout` / `firstin` | — | 顶点结点里出边表 / 入边表的头指针 |
| `tlink` | tail link | 弧在**出边链**上的后继（"弧尾相同"的下一条弧） |
| `hlink` | head link | 弧在**入边链**上的后继（"弧头相同"的下一条弧） |
| 邻接多重表 | adjacency multilist | 无向图的每条边只生成**一个**边结点，两个端点共用 |
| `ivex` / `jvex` | — | 边结点的两个端点编号，实现中约定 `ivex < jvex` |
| `ilink` / `jlink` | — | 依附于 `ivex` / 依附于 `jvex` 的下一条边 |
| `mark` | — | 边是否已被访问过的标志（邻接多重表的传统字段） |

一句话记忆：**十字链表是"按弧交叉"，邻接多重表是"按边共享"。**

## 二、核心性质与定理

### 1. 空间：十字链表 n + e，邻接多重表 n + e（而邻接表是 n + 2e）

十字链表的顶点表有 n 个结点（每个含 2 个指针），弧结点恰好 e 个（每条弧一个，含 2 个链指针）。
所有出边链的结点总数为 e（每条弧恰好在一条出边链上），所有入边链的结点总数也是 e，但它们指向**同一批** e 个结点。

邻接多重表：n 个顶点结点 + e 个边结点。
对比无向图邻接表：n 个顶点结点 + 2e 个边结点。**每条边省下一个结点**。
按 32 位估算，一个边结点 `(ivex, jvex, weight, mark, ilink, jlink)` ≈ 4+4+4+4(对齐)+4+4 = 24 字节，
邻接表每边两份 = 48 字节，邻接多重表每边 24 字节。10 万条边的无向图，**省下约 2.4 MB**，这就是它存在的理由。

### 2. 度数与弧数的关系

设 `outdeg(v)`、`indeg(v)` 分别为出度、入度，e 为弧数，则恒有

```
Σ outdeg(v) = Σ indeg(v) = e
```

因为每条弧恰好贡献一个出度（在弧尾）和一个入度（在弧头）。这也是"横向链（tlink）总长 = 纵向链（hlink）总长 = e"的另一种说法。

**推论**：十字链表可以在 Θ(n+e) 时间内一次求出**所有**顶点的入度和出度；邻接表求所有入度则要 O(n(n+e))，必须改用"逆邻接表"或额外计数数组。

### 3. 转置（求逆图）只需交换指针，Θ(n+e)，不分配任何新结点

逆图 `Gᵀ` 的弧集是 `{<v,u> | <u,v> ∈ E}`。
观察：原图中**以 u 为弧头**的弧，在 Gᵀ 中恰好是**以 u 为弧尾**的弧。也就是说

> **Gᵀ 的出边表 ≡ G 的入边表；Gᵀ 的入边表 ≡ G 的出边表。**

于是只要做三件事：

1. 对每个顶点交换 `firstin` 与 `firstout` → 顶点表就正确了；
2. 对每条弧交换 `hlink` 与 `tlink` → 链内后继关系就正确了；
3. 对每条弧交换 `tail` 与 `head` → 端点数据就正确了。

代价：2n 次指针交换 + 3e 次字段交换，即 Θ(n+e)，空间 O(1)。
对比邻接矩阵求逆是 Θ(n²)，邻接表要重建整张表（e 次 new）。这是十字链表最漂亮的性质，也是它在网络流（需反复求残量网络反向边）里被使用的原因。

### 4. 邻接多重表"一条边一个结点"带来的两个后果

- **好处**：删除边不涉及"第二份副本"，不会出现两处不一致；若边结点带双向指针或已知前驱，可做到 O(1)。
- **代价**：边结点的两个指针字段分别服务两个端点，插入一条边时**必须挂两次**，而且两次用的是**不同字段**；遍历某顶点的邻边时**必须判断**当前结点里 `v` 是 `ivex` 还是 `jvex`，才能决定沿 `ilink` 还是 `jlink` 前进。这是所有实现出错的第一现场。

### 5. DFS/BFS 顺序由链表顺序决定

十字链表/邻接多重表都是**头插法**建表，于是"最后插入的边排在最前"。同一张图，插入顺序不同 → 链表顺序不同 → DFS 序、BFS 序不同，但**遍历结果集合**（连通性、可达性）不变。做题时若要求"按编号递增访问"，必须尾插或对邻边排序。

## 三、存储结构

### 3.1 十字链表（有向图）

```cpp
// 弧结点：一条弧一个，同时挂在两条链上
typedef struct ArcBox {
    int tailvex, headvex;          // 弧尾、弧头顶点下标
    struct ArcBox *hlink, *tlink;  // 弧头相同的下一条弧 / 弧尾相同的下一条弧
    InfoType *info;                // 权值等信息
} ArcBox;

// 顶点结点：数据的顺序存储 + 两条链的头指针
typedef struct VexNode {
    VertexType data;
    ArcBox *firstin, *firstout;    // 第一条入弧 / 第一条出弧
} VexNode;

typedef struct {
    VexNode xlist[MAXV];           // 顶点表（顺序）
    int vexnum, arcnum;            // 顶点数、弧数
} OLGraph;
```

C++ 版本（本仓库代码的写法，用 `vector<VexNode>` 代替定长数组）：

```cpp
struct ArcBox {
    int tail, head, weight;
    ArcBox *hlink, *tlink;
};
struct VexNode {
    std::string name;
    ArcBox *firstin, *firstout;
};
```

**图解**：弧 `<A,C>` 这一个结点，既出现在 A 的出边链上（A 沿 `tlink` 能走到它），又出现在 C 的入边链上（C 沿 `hlink` 能走到它）。两条链在这个结点上"十字交叉"。

### 3.2 邻接多重表（无向图）

```cpp
// 边结点：一条无向边一个，两个端点共用
typedef struct EBox {
    VisitIf mark;                  // 访问标记：这条边是否走过
    int ivex, jvex;                // 边的两个端点（约定 ivex < jvex）
    struct EBox *ilink, *jlink;    // 依附于 ivex / jvex 的下一条边
    InfoType *info;                // 权值
} EBox;

// 顶点结点
typedef struct VexBox {
    VertexType data;
    EBox *firstedge;               // 第一条依附于该顶点的边
} VexBox;

typedef struct {
    VexBox adjmulist[MAXV];
    int vexnum, edgenum;
} AMLGraph;
```

### 3.3 顺序 vs 链式：四种存储横向对比

| 存储方式 | 适用 | 空间 | 边结点个数（无向图 e 条边） | 典型弱项 |
| --- | --- | --- | --- | --- |
| 邻接矩阵 | 稠密图、需 O(1) 判边 | O(n²) | 不需要 | 稀疏图浪费 |
| 邻接表 | 稀疏图、有向/无向通用 | O(n+e) | 2e | 求入度慢；双份副本 |
| 十字链表 | 稀疏**有向**图 | O(n+e) | e（弧结点） | 只适合有向图 |
| 邻接多重表 | 稀疏**无向**图 | O(n+e) | e | 遍历要判断 ivex/jvex |

## 四、核心操作的实现思路

### 4.1 十字链表：插入弧 `<u,v>`（O(1)，头插）

```cpp
ArcBox* a = new ArcBox{u, v, w};
a->tlink = vex[u].firstout;  vex[u].firstout = a;   // 挂到 u 的出边链
a->hlink = vex[v].firstin;   vex[v].firstin  = a;   // 同时挂到 v 的入边链
```

两个 if 都不用写，因为"出边链用 tlink、入边链用 hlink"是固定的。**注意这两行必须都做**，少写一行就是"半个十字"。

### 4.2 十字链表：求入度 / 出度（O(度)）

```cpp
int outDegree(int u) { int c=0; for (ArcBox* a=vex[u].firstout; a; a=a->tlink) ++c; return c; }
int inDegree (int u) { int c=0; for (ArcBox* a=vex[u].firstin;  a; a=a->hlink) ++c; return c; }
```

关键：**入度走 `firstin`+`hlink`，出度走 `firstout`+`tlink`**。指针与链必须配对，混用就会读到别人的边。

### 4.3 十字链表：删除弧 `<u,v>`

必须在两条链上各摘一次，且两次都要处理"被删的是链首"的情况：

1. 沿 `u` 的出边链找 `head == v` 的结点，记录前驱；若前驱为空则改 `firstout`，否则改 `prev->tlink`；
2. 沿 `v` 的入边链**按指针**找同一个结点（不要按数据找，否则遇到平行弧会删错），同样处理 `firstin` / `prev->hlink`；
3. 释放结点。

### 4.4 十字链表：转置（Θ(n+e)）

```cpp
for (VexNode& vn : vex) swap(vn.firstin, vn.firstout);
for (ArcBox* a : arcs) { swap(a->tail, a->head); swap(a->hlink, a->tlink); }
```

不需要 new、不需要遍历边表、不需要辅助数组。交换完 `outDegree(u)` 自然等于原来的 `inDegree(u)`，可作自检。

### 4.5 邻接多重表：插入边 `(u,v)`（挂两次，用不同字段）

```cpp
int i = min(u,v), j = max(u,v);        // 约定 ivex < jvex
EdgeBox* e = new EdgeBox{i, j, w};
attach(vex[u], u, e);                  // 挂到 u 的链
attach(vex[v], v, e);                  // 挂到 v 的链

void attach(MVexNode& vn, int v, EdgeBox* e) {
    if (e->ivex == v) e->ilink = vn.firstedge;   // v 是 ivex → 用 ilink
    else              e->jlink = vn.firstedge;   // v 是 jvex → 用 jlink
    vn.firstedge = e;
}
```

这正是"必须判断"的地方：同一个结点的两个指针字段被两个端点分别占用。

### 4.6 邻接多重表：遍历 v 的邻边（每步都要判断）

```cpp
for (EdgeBox* e = vex[v].firstedge; e; ) {
    int w  = (e->ivex == v) ? e->jvex : e->ivex;     // 另一端
    EdgeBox* nxt = (e->ivex == v) ? e->ilink : e->jlink;  // 先算后继
    // ... 处理边 (v,w) ...
    e = nxt;
}
```

**必须先算好后继再处理**，因为处理过程中若删除了 `e`，`e->ilink` 已不可读。

### 4.7 邻接多重表：删除边 `(u,v)`

摘链要改前驱的"对应字段"：

```cpp
if (prev == nullptr)          vn.firstedge = nxt;   // 删的是链首
else if (prev->ivex == v)     prev->ilink   = nxt;  // 前驱沿 ilink 指向我
else                          prev->jlink   = nxt;
```

已知边结点指针时，仍需找前驱（O(度)）；若把边结点改成双向（多加两个指针），才能做到 O(1)。**但无论如何，边只有一个副本，不存在"改了一处忘了另一处"的风险**——这才是它相对邻接表的真实优势。

### 4.8 邻接多重表：用 mark 做"每条边恰好一次"的 DFS

```cpp
if (!e->mark) {                 // 这条边还没走过
    e->mark = true;             // 立刻标记
    if (!vis[w]) {              // 通向未访问顶点 → 生成树的树边
        print(v, w);  dfs(w);
    }
}
```

树边恰好 n−1 条（连通时），`mark` 最终全为 true。**边标记不能代替顶点标记**：一条边的两端可能都已被访问（回边），`mark` 保证不走第二遍，但若没有 `vis[]`，DFS 仍会从别的路径回到已访问顶点并继续展开，导致重复访问与死循环。

## 五、复杂度小结

| 操作 | 邻接矩阵 | 邻接表 | 十字链表（有向） | 邻接多重表（无向） |
| --- | --- | --- | --- | --- |
| 空间 | O(n²) | O(n+e) | O(n+e) | O(n+e)，边结点数为邻接表的一半 |
| 求 v 的出度 | O(n) | O(出度) | **O(出度)** | 不适用 |
| 求 v 的入度 | O(n) | O(n+e)（全表扫） | **O(入度)** | 不适用 |
| 求全部顶点入度 | O(n²) | O(n(n+e)) | **Θ(n+e)** | 不适用 |
| 判断弧 `<u,v>` 是否存在 | **O(1)** | O(出度 u) | O(出度 u) | O(度 u)（边） |
| 插入一条弧/边 | O(1) | O(1) | O(1) | O(1)（挂两次） |
| 删除一条弧/边 | O(1)（置 INF） | O(度 u + 度 v) | 两条链各 O(链长) | 两条链各 O(链长)，无副本风险 |
| DFS / BFS | O(n²) | O(n+e) | O(n+e) | O(n+e) |
| 求转置 / 逆图 | O(n²) | O(n+e)（重建） | **Θ(n+e)，原地 O(1) 额外空间** | 不适用 |
| 存 e 条边的结点数 | — | 2e | e | e |

## 六、常见易错点

1. **`tlink` / `hlink` 记反**。记法：`t` = tail，所以 `tlink` 是"弧尾相同"→ 属于**出边链**；`h` = head，`hlink` 属于**入边链**。
2. **求入度却走了出边链**：`firstin` 必须配 `hlink`，`firstout` 必须配 `tlink`。混用会读到别的顶点的弧，甚至成环死循环。
3. **插入弧只挂了一条链**：十字链表的两行赋值必须都写，否则这条弧只出现在一个方向的表里。
4. **邻接多重表两次 `attach` 都写 `ilink`**：会把 `jlink` 覆盖，链断裂。必须按 `e->ivex == v` 判断用哪个字段。
5. **遍历邻边时固定走 `ilink`**：必须每步判断 `e->ivex == v`，否则走到一半就跑到别的顶点的链上去了。
6. **删除边忘了处理链首**：`firstedge` / `firstout` / `firstin` 也要跟着改，不能只改 `prev->next`。
7. **按数据而非指针删弧**：有平行弧（相同 `<u,v>` 出现多次）时，出边链上找到的那条与入边链上要摘的那条可能不是同一个结点，必须用指针定位。
8. **用输入顺序手算 DFS 序**：头插法建表后链表是逆序的，DFS/BFS 序与"输入顺序"不同。写预期输出前必须按链表实际顺序推。
9. **以为 `mark` 可以替代 `vis[]`**：`mark` 标的是边，不是顶点；两者都要有。
10. **自环 `(v,v)`**：在邻接多重表里会退化成 `ivex == jvex`，同一结点的两个指针挂进同一链，遍历时被走两次。实践中建表直接忽略自环。
11. **拿十字链表存无向图**：每条无向边要存两条弧，等于"每条边两个结点"，还不如直接用邻接多重表。
12. **忘记释放**：这两种结构都是手工 `new`，教学代码里要写析构函数遍历释放；含裸指针的类应 `= delete` 掉拷贝构造，避免二次释放。
