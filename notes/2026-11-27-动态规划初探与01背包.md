# 动态规划初探与 01 背包问题（课程 40~41）

## ① 基本概念与术语表

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 动态规划 | Dynamic Programming (DP) | 把原问题分解为相互重叠的子问题，按顺序求解并保存子问题答案，避免重复计算的方法 |
| 重叠子问题 | Overlapping Subproblems | 用递归分解时，同一子问题会被反复遇到（如 fib(5) 会算多次 fib(3)），这是 DP 能提速的根本原因 |
| 最优子结构 | Optimal Substructure | 原问题的最优解可以由子问题的最优解构造出来。背包问题里"前 i 件、容量 j 的最优"由"前 i-1 件、容量 j 或 j-w[i]"推出 |
| 无后效性 | No Aftereffect | 某阶段的状态一旦确定，之后的过程不受此前各状态转移方式的影响，只与当前状态值有关 |
| 状态 | State | 对子问题的精确刻画，写成 `dp[i][j]`（第 i 个阶段、第 j 个取值维度） |
| 转移方程 | Transition Equation | 状态之间如何推导：`dp[i][j] = f(dp[i-1][*], ...)`，这是 DP 的核心 |
| 记忆化搜索 | Memoization | 自顶向下：先写暴力递归，再加一个数组缓存已算过的子问题 |
| 制表法 | Tabulation | 自底向上：按阶段顺序把 dp 表填满，通常比记忆化少递归开销、可再压维 |
| 0/1 背包 | 0/1 Knapsack | n 件物品，第 i 件重量 w[i]、价值 v[i]，每件**只能选或不选**，容量 W 内总重量不超，求总价值最大 |
| 完全背包 | Unbounded Knapsack | 每件物品可选无限次，与 0/1 背包只差"容量正序/逆序"一个字 |

## ② 核心性质与推导

**性质 1：暴力递归的指数级爆炸。**
对每件物品做"选 / 不选"两种决策，朴素递归时间 O(2^n)。以 20 件物品计需约百万次，30 件约十亿次——但其中大量子问题 `(i, remain)` 是重复的，子问题总数只有 n × W 个。这就是记忆化的收益来源。

**性质 2：0/1 背包的状态定义与转移方程。**
定义 `dp[i][j]` = 只考虑前 i 件物品、背包容量为 j 时能取得的最大价值。对第 i 件物品只有两种选择：

```
dp[i][j] = max( dp[i-1][j]              ,  不选第 i 件
               dp[i-1][j - w[i]] + v[i] ,  选第 i 件，前提 j >= w[i] )
```

推导：若选第 i 件，则前 i-1 件只能在容量 j-w[i] 内安排（否则超重），两部分拼起来就是 j-w[i] 容量下的最优 + v[i]；若不选，则退化为前 i-1 件在容量 j 下的最优。两者取大即覆盖了全部决策空间，且满足最优子结构与无后效性。

**性质 3：一维滚动数组与"为什么必须逆序"。**
观察转移方程，第 i 行只依赖第 i-1 行，可把二维压成一维：`dp[j] = max(dp[j], dp[j-w[i]] + v[i])`。
关键在于更新 dp[j] 时用到的 `dp[j-w[i]]` 必须还是"上一行（i-1）"的旧值：

- **j 从 W 逆序到 w[i]**：算 dp[j] 时，dp[j-w[i]] 尚未被本轮更新，仍是 i-1 行的旧值 → 正确，且每件物品最多用一次（0/1 语义）。
- **j 从 w[i] 正序**：dp[j-w[i]] 已被本轮更新过，相当于"同一件物品已经放过了再放一次" → 变成了完全背包的转移。

一句话记忆：**0/1 背包一维写法必须逆序容量；正序就是完全背包。**

**性质 4：DP 与贪心的区别。**
贪心（按单位价值 v/w 从高到低装）对 0/1 背包**不保证最优**：反例 物品 (w=4, v=6)、(w=3, v=4)、(w=3, v=4)，W=6。单位价值 1.5 > 1.33，贪心先装第一件，剩容量 2 什么都装不下，得 6；DP 取后两件恰好装满得 8。贪心失败的原因是"局部的最优选择堵死了全局更优的组合"（第一件占用了本可用于两件小物品的容量），而 DP 对所有子决策保留比较。

**性质 5：时间下界。**
0/1 背包是 NP-hard 问题，DP 解法 O(nW) 是**伪多项式**（复杂度与数值 W 成正比而非输入位数），W 极大时仍不可行——这也是后续会引入贪心近似、分支限界等手段的原因。

## ③ 存储结构

DP 的"数据结构"就是一张（或多张）表，通常用顺序存储（数组/`vector`），因为需要按下标随机访问阶段与维度：

```cpp
// 记忆化用的缓存表：memo[i][j] = -1 表示"前 i 件、剩余容量 j"还没算过
vector<vector<int>> memo(n + 1, vector<int>(W + 1, -1));

// 自底向上制表：dp[i][j] = 前 i 件物品、容量 j 的最大价值
vector<vector<int>> dp(n + 1, vector<int>(W + 1, 0));
```

顺序表 vs 链式结构对比：

| 对比项 | 顺序表（DP 常用） | 链式结构 |
| --- | --- | --- |
| 随机访问 dp[i][j] | O(1)，转移方程要求 | 无法 O(1) 定位 |
| 空间 | 恰好 (n+1)×(W+1)，可滚动压缩 | 每个节点额外指针开销 |
| 按阶段顺序填充 | 天然连续、缓存友好 | 无连续阶段的语义 |
| 结论 | DP 制表一律用数组 | 不适用 |

## ④ 核心操作实现思路

1. **朴素递归 `solve(i, remain)`**：`i` 是当前考虑第几件，`remain` 是剩余容量。`remain <= 0` 或 `i == n` 返回 0；否则返回 `max(solve(i+1, remain), v[i] + solve(i+1, remain - w[i]))`（后者仅当 `w[i] <= remain`）。
2. **记忆化**：进入函数先查 `memo[i][remain]`，命中直接返回；算完写回。复杂度从 O(2^n) 降到 O(nW)。
3. **二维制表**：外层 `i` 从 1 到 n（阶段），内层 `j` 从 0 到 W（维度），按转移方程填表；边界 `dp[0][*] = 0`。
4. **方案还原**：从 `(n, W)` 出发倒着走表：若 `dp[i][j] != dp[i-1][j]` 说明第 i 件被选中，记录后 `j -= w[i]`、`i--`；否则 `i--`。注意倒推得到的顺序是逆序，最后 reverse。
5. **一维滚动数组**：删掉 i 维，`j` 从 W 逆序枚举到 `w[i]`，`dp[j] = max(dp[j], dp[j-w[i]] + v[i])`。
6. **完全背包对照**：同一份代码只把内层 `j` 改成正序枚举，即可处理"每件物品无限件"的场景——用于验证性质 3。

## ⑤ 复杂度小结

| 方法 | 时间 | 空间 | 备注 |
| --- | --- | --- | --- |
| 朴素递归 | O(2^n) | O(n) 递归栈 | n=30 就基本跑不动 |
| 记忆化搜索 | O(nW) | O(nW) | 代码改动最小，只加一个缓存 |
| 二维制表 | O(nW) | O(nW) | 支持方案还原 |
| 一维滚动数组 | O(nW) | O(W) | 必须逆序枚举容量 |
| 完全背包（一维正序） | O(nW) | O(W) | 与 0/1 背包只差枚举方向 |
| 方案还原 | O(n+W) | O(1) 额外 | 依赖二维表回溯 |

## ⑥ 常见易错点

1. **一维滚动数组正序枚举**：直接把 0/1 背包写成正序，结果算成完全背包，样例一跑就比手算大——这是最高频错误。
2. **状态定义含混**：`dp[i][j]` 必须明确是"容量**不超过** j"（本文取法）还是"恰好装满 j"（后者初始化 `dp[0][0]=0`、其余为 -∞，且答案要扫 `max(dp[n][0..W])`）。两种定义混用会导致边界错。
3. **"恰好装满"用 -∞ 而不是 -1**：用 -1 当"不可达"标记时，转移里 `-1 + v[i]` 会伪装成一个不小的合法值，必须用足够小的负数（如 `INT_MIN/2`）防溢出。
4. **记忆化数组没有初值标记**：忘了把未访问状态初始化为 -1，或者把合法的 0 值当成"没算过"再次计算。
5. **方案还原顺序**：倒推得到的是物品编号逆序，忘记 reverse 输出会变成 "4 2" 而不是 "2 4"。
6. **物品编号 0 起还是 1 起**：二维表留出第 0 行/列做边界，循环从 1 开始，别写成 `for (i = 0; i < n; ...)` 又同时引用 `dp[i-1]`。
7. **贪心陷阱**：拿"单位价值最大"当 0/1 背包的最优策略（见性质 4 反例），考试常考。
8. **n 与 W 的量纲混淆**：O(nW) 中的 W 是数值大小，不是输入规模——W=10^9 时二维表开不出来，属于伪多项式。
