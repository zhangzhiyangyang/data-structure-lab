# 2026-10-25 二叉树的线索化

> 对应课程第 11 期。线索化 = 把二叉链表里大量"空着的" n+1 个指针利用起来，
> 让它们指向遍历序列中的前驱/后继，从而做到**不用递归、不用栈、不用队列**
> 就能按某种次序遍历二叉树。

## 1. 基本概念与术语表

| 术语 | 含义 |
| --- | --- |
| 线索（thread） | 指向该结点在某种遍历序列下**前驱**或**后继**的指针 |
| 线索链表 | 结点结构中既存孩子指针又存线索的二叉链表 |
| 线索化 | 对二叉树按某种次序遍历一遍，把空指针改写为线索的过程 |
| 中序线索树 | 按**中序**次序建立线索的二叉树（最常用，考试默认） |
| 前序/后序线索树 | 按前序/后序次序建立线索的二叉树 |
| tag 标志位 | 区分指针存的是"孩子"（0/Link）还是"线索"（1/Thread） |

为什么要线索化？n 个结点的二叉链表共有 `2n` 个指针域，实际用了 `n-1` 个
（n-1 条边），**浪费了 n+1 个空指针**。线索化把这些空指针变成前后驱线索。

## 2. 核心性质

1. **n+1 个线索的分配**：n+1 个空指针中，恰好 1 个空左指针（中序序列第一个结点的
   左孩子为空，指向 null 或头结点）和 1 个空右指针（最后一个结点的右孩子为空），
   其余 `n-1` 个空指针中，若干个存前驱线索、若干个存后继线索。
   严格地说：空左指针中，1 个指向 null，n 个里……考试常考结论：
   **前驱线索数 = 空左指针数 - 1（不计头结点）**，直觉记法即可，别背复杂公式。
2. **线索的二义性**：同一条线索既可理解为前驱也可理解为后继（视方向而定），
   所以必须靠 tag 区分孩子指针和线索指针，不能只靠是否为 null 判断。
3. **中序线索树的优点**：找中序后继 O(1)（若右指针是线索）或 O(h)（右子树最左结点），
   且无需栈、无递归，遍历空间复杂度 O(1)。
4. **后序线索树找后继不便**：需要知道双亲，纯二叉链表做不到，必须加双亲指针；
   这是"中序线索化最实用"的原因。

## 3. 存储结构

```cpp
// 线索二叉树结点：在普通二叉链表上加了两个标志位
typedef char ElemType;
struct ThreadNode {
    ElemType data;          // 数据域
    ThreadNode *lchild;     // 左孩子 或 前驱线索（由 ltag 决定）
    ThreadNode *rchild;     // 右孩子 或 后继线索（由 rtag 决定）
    int ltag;               // 0 = Link 孩子指针；1 = Thread 前驱线索
    int rtag;               // 0 = Link 孩子指针；1 = Thread 后继线索
};

// 对比：普通二叉链表
struct BiTNode {
    ElemType data;
    BiTNode *lchild, *rchild;   // 没有标志位，空指针无法区分含义
};
```

| 项目 | 顺序存储 | 链式（二叉链表） | 线索链表 |
| --- | --- | --- | --- |
| 找孩子 | 下标计算 O(1) | 指针 O(1) | 指针 O(1) |
| 找前驱/后继 | 需要遍历 | 需要栈/递归 O(h) 空间 | **线索直达，无需栈** |
| 空间浪费 | 严重（满二叉树编号） | n+1 个空指针 | 空指针全部利用 |

## 4. 核心操作实现思路

### 4.1 中序线索化（递归 + 全局/引用前驱指针）

```
线索化 = 中序遍历一遍，每个结点访问时做两件事：
  1) 若 pre 的右孩子为空：pre->rchild = 当前结点，pre->rtag = 1（后继线索）
  2) 若当前结点左孩子为空：当前->lchild = pre，当前->ltag = 1（前驱线索）
  3) pre = 当前结点
结束时把 pre 的 rchild 置 null（rtag 保持 1 或 0 视情况处理为无后继）。
```

**关键点：线索化过程中要小心别把"线索"当成"孩子"递归进去**——递归入口先
判断 `ltag == 0` 才递归左子树。

### 4.2 中序线索遍历（非递归、O(1) 空间）

```
p = 中序序列第一个结点（从根一直往左走，直到 ltag == 1）
循环：访问 p；然后 p = 中序后继(p)
中序后继：
  若 p->rtag == 1      → 后继就是 p->rchild（线索直达）
  否则 p 右子树最左结点（一路 ltag==0 往左）
```

### 4.3 中序线索树找前驱（对称操作）

```
若 p->ltag == 1      → 前驱就是 p->lchild
否则 p 左子树最右结点（一路 rtag==0 往右）
```

### 4.4 逆中序遍历

从中序序列最后一个结点（根一路往右）开始，反复"找前驱"即可，同样 O(1) 空间。

## 5. 复杂度小结

| 操作 | 时间 | 空间 | 说明 |
| --- | --- | --- | --- |
| 中序线索化（建树） | O(n) | O(h) 递归栈 | 一次性代价 |
| 线索化后中序遍历 | O(n) | **O(1)** | 普通二叉树需要 O(h) 栈 |
| 找中序后继 | O(1) 或 O(h) | O(1) | rtag=1 时 O(1) |
| 找中序前驱 | O(1) 或 O(h) | O(1) | ltag=1 时 O(1) |
| 插入/删除结点 | O(h) | O(1) | 需同时维护线索，实现繁琐 |

## 6. 常见易错点

1. **忘记 tag 标志位**：只用空指针判断"是不是线索"，遇到既有孩子又被线索化的
   情况会错乱。tag 与指针必须成对维护。
2. **线索化时把线索当孩子递归**：线索化函数里递归左子树前必须判 `ltag == 0`，
   否则沿着前驱线索走出无限递归（这是本主题最经典的 bug，练习题 2 会让你踩一次）。
3. **pre 初始化**：pre 应为 null，第一个访问的结点没有前驱；结束时 pre 的
   后继线索要正确置空，否则尾结点右指针成野指针。
4. **头结点法 vs 直接法**：教材（严蔚敏）用带头结点的线索链表，头结点 lchild 指根、
   rchild 指中序最后一个结点，形成双向循环链；本文代码用直接法（空指针存 null），
   两者找后继逻辑略有差别，考试按题目给的存储结构作答。
5. **线索化后不能再用普通遍历**：`inorder(root)` 递归会因线索指针访问到已访问
   结点导致死循环或重复输出。
6. **先序线索树**：线索化递归函数中访问完当前结点后，若直接递归右子树，可能
   沿着刚写的后继线索又访问当前结点——先序线索化时递归右子树前要判 `rtag == 0`。
7. **中序后继的判断顺序**：先看 `rtag`，再看右孩子是否存在，两个条件不能颠倒。
8. **求"前驱的前驱"**：链式跳线索时注意空指针检查，`while (p->ltag == 0)` 的
   循环里 p 可能为 null（空树）。

## 7. 练习题（答案在配套代码 code/2026-10-25-threaded_binary_tree.cpp 的 main 里验证）

1. 给定 9 个结点、以 A 为根的二叉树（先序 A B D G E H I C F，中序 G D B A H E I C F），
   手工画出它的中序线索二叉树，标出所有线索的方向与 tag 值。
2. 写一个故意不判 `ltag` 就递归的线索化函数，观察运行现象（死循环/越界），
   然后修正它。理解"线索不能当孩子递归"。
3. 在中序线索树上实现"找指定结点的中序后继"函数，并用它写出非递归中序遍历；
   对比普通递归中序遍历的结果，两者输出必须完全一致。
4. 实现逆中序遍历（从最后一个结点出发反复找前驱），验证输出为中序序列的倒序。
5. 判断题并说理由：
   (a) 中序线索树中任意结点都能 O(1) 找到后继。
   (b) n 个结点的线索二叉树比同形态的二叉链表多占 O(n) 空间。
   (c) 后序线索树上找后继需要知道双亲指针。
