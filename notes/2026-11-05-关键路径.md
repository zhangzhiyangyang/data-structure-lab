# 关键路径（Critical Path）—— AOE 网上的最长路

> 对应课程第 28 期。一句话：把工程画成 **AOE 网**（顶点是事件、边是活动、边权是工期），
> 从源点到汇点的**最长路径**就是关键路径，它的长度就是整个工程的最短完工时间。
> 这条路径上任何一项活动拖延一天，整个工程就晚一天。

## ① 基本概念与术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| AOE 网（Activity On Edge） | 顶点表示**事件**、有向边表示**活动**、边权表示活动持续时间的带权 DAG | 与 AOV 网的区别：活动在**边**上，不是顶点上 |
| 事件（event） | 一个"时间点"，表示它前面的活动全部完成、后面的活动可以开始 | 顶点本身不耗时，耗的是它出边上的权 |
| 活动（activity） | 一条边 `i → j`，表示"事件 i 发生后开始，完成后触发事件 j" | 活动耗时 = 边权 w(i,j) |
| 源点（source） | 入度为 0 的顶点，工程开始事件 | 全工程唯一（多个时要加虚拟源点） |
| 汇点（sink） | 出度为 0 的顶点，工程结束事件 | 同上，多个时要加虚拟汇点 |
| ve[j] | 事件 j 的**最早**发生时间 = 从源点到 j 的**最长**路径长度 | earliest，正推得到 |
| vl[j] | 事件 j 的**最迟**发生时间 = 在不推迟总工期的前提下 j 最晚能发生的时间 | latest，逆推得到 |
| e(a) | 活动 a=`<i,j>` 的**最早**开始时间，`e = ve[i]` | "事件 i 一到就能开工" |
| l(a) | 活动 a 的**最迟**开始时间，`l = vl[j] - w(i,j)` | 再晚就拖累事件 j |
| 时间余量 d(a) | `d = l - e`，也叫松弛时间（slack） | 恒有 `d ≥ 0`（见 ②-4） |
| 关键活动 | `d = 0` 的活动，即一天都拖不起的活动 | 关键活动一定在**某条**关键路径上 |
| 关键路径 | 从源点到汇点、全部由关键活动组成的路径 | 长度 = 总工期；**一般不唯一** |
| 工期 | 工程从开始到全部完成的耗时 = `ve[汇点]` | 也是"最长路径长度" |

## ② 核心性质 / 定理

### 1. `ve` 的递推（正推，按拓扑序）

```
ve[源点] = 0
ve[j] = max{ ve[i] + w(i,j) }  对 j 的所有入边 <i,j> 取最大
```

**推导**：事件 j 发生的前提是"所有以 j 为终点的活动都已完成"。活动 `<i,j>` 最早在 `ve[i]` 开始，
最早在 `ve[i] + w` 完成。要等**最慢**的那条入边完成，所以取 **max**。
这也是"事件最早时间 = 最长路"的直接来源。

注：必须按**拓扑序**正推，否则计算 `ve[j]` 时前驱的 `ve[i]` 还没定。

### 2. `vl` 的递推（逆推，按逆拓扑序）

```
vl[汇点] = ve[汇点]
vl[i] = min{ vl[j] - w(i,j) }  对 i 的所有出边 <i,j> 取最小
```

**推导**：活动 `<i,j>` 最迟必须在 `vl[j]` 之前**开始**才能不拖累 j，于是事件 i 最迟要在
`vl[j] - w` 时刻发生。i 往往有多个后继，必须同时满足所有后继的限制，所以取 **min**。
初值必须是 `ve[汇点]`（不能是 INF），因为总工期定死在 `ve[汇点]`。

### 3. 定理：`ve[汇点]` = 关键路径长度 = 最短工期

- **上界**：对任意顶点 j，`ve[j] ≥ 任意一条从源点到 j 的路径长度`（对路径长度归纳，递推式取 max 即得）。
  故任一条源→汇路径长度 `≤ ve[汇点]`。
- **可达**：从汇点沿"取到 max 的那个前驱"一路回溯到源点，得到的路径长度恰为 `ve[汇点]`。
- **工期**：工程完成必须等所有活动结束，任一条源→汇路径上的活动都要依次做完，故
  `工期 ≥ 任一路径长度`；而上面那条路径就是 `ve[汇点]`，所以 `工期 = ve[汇点]`。

一句话：**关键路径是"最长"路径，却决定了"最短"工期**——这是最容易背反的一句。

### 4. 定理：`0 ≤ l(a) - e(a)` 恒成立

对活动 `a=<i,j>`，需证 `ve[i] ≤ vl[j] - w`。
由 ②-1 的递推，`ve[j] ≥ ve[i] + w`；由 ②-2，`vl[j] ≤ ...` 反向使用可得 `vl[j] ≥ ve[j]`（沿逆拓扑序归纳：
汇点取等号，非汇点 `vl[i] = min(vl[j]-w) ≥ min(ve[j]-w) ≥ ve[i]`）。
两式合并：`vl[j] ≥ ve[j] ≥ ve[i] + w`，即 `vl[j] - w ≥ ve[i]`，余量非负。
**余量为负 = 计算或数据出错了**（多半是漏了拓扑序、初值给错，或图不是 DAG）。

### 5. 定理：`a` 是关键活动 ⇔ `a` 在某条关键路径上

- 必要性：若 `ve[i] = vl[j] - w`，取"源→i 的最长路（长度 `ve[i]`）"+"边 `<i,j>`"+"j→汇的
  最迟路（长度 `vl[j]` 对应部分）"，拼起来长度正好 `ve[i] + w + (T - vl[j]) = T`，是一条关键路径。
- 充分性：关键路径长度 = T，路径上任意活动都在"卡时间"，推迟它必然使 T 增大，故 `d = 0`。

### 6. 关键路径不唯一，且缩短工期的正确姿势

- 一个 AOE 网可能有多条长度都等于 T 的路径，此时它们**全部**是关键路径，关键活动的并集才是"要盯的集合"。
- **只有缩短关键活动才可能缩短工期**；缩短非关键活动（`d > 0`）在余量耗尽前对工期**毫无影响**。
- 即便缩短关键活动，也可能只缩到"次长路径"的长度就卡住：一旦某条关键路径被缩到与其他路径等长，
  别的路径就变成新的关键路径，工期不再下降。所以**必须同时缩短所有关键路径**才能真正省时间。

### 7. 复杂度

拓扑排序 + 正推 + 逆推 + 扫一遍活动，都是线性的：**O(V + E)**。
这已经是最优量级（每条边至少要看一次）。输出"全部关键路径"本身可能指数级多，那部分不算在 O(V+E) 里。

## ③ 存储结构

AOE 网是**带权有向图 + 需要反复遍历出边**，所以选 **边集数组 + 邻接表（出边表）**：

```cpp
// 一条活动：从事件 u 出发，到事件 v，持续 w 天
struct Edge {
    int from, to, w;      // 也常写成 u, v, weight
};

// AOE 网：n 个事件（顶点），m 条活动（边）
struct AOE {
    int n;                          // 事件数 V
    vector<Edge> edges;             // 边集：按下标访问每条活动，算 e/l/余量最方便
    vector<vector<int>> out;        // 出边表：out[u] 存"从 u 出发的活动"的 edges 下标

    explicit AOE(int n_) : n(n_), out(n_) {}

    // 加一条活动 u → v（耗时 w），返回它在 edges 里的下标（= 活动编号）
    int addActivity(int u, int v, int w) {
        edges.push_back({u, v, w});
        out[u].push_back(static_cast<int>(edges.size()) - 1);
        return static_cast<int>(edges.size()) - 1;
    }
};
```

只存**出边表**就够用了：
正推 `ve` 时按拓扑序遍历 u 的出边做"推送"（`ve[v] = max(ve[v], ve[u]+w)`）；
逆推 `vl` 时按**逆拓扑序**遍历 u 的出边做"拉取"（`vl[u] = min(vl[u], vl[v]-w)`），
两种顺序下对面那个端点的值都已经是最终值，所以不需要逆邻接表。

> 教材（严蔚敏）为了"入边驱动"地算 `ve`，会同时建**逆邻接表**（`in[v]` 存所有入边）。
> 那是为了配合教材版的写法；用拓扑序 + 出边表等价且更省一半空间。

| | 邻接表（出边，推荐） | 邻接矩阵 |
| --- | --- | --- |
| 空间 | O(V + E) | O(V²) |
| 遍历某事件的全部后继活动 | O(出度) | O(V)（扫一整行） |
| 统计入度（判源点/拓扑排序） | O(V + E) 一次扫边 | O(V²) |
| 取某条活动的权 | O(1)（边集下标） | O(1) |
| 适用场景 | 工程图几乎都是稀疏图 | 稠密图 / 教学演示 |

## ④ 核心操作的实现思路

整体流程五步，顺序不能乱：

```
1. 建图，统计入度
2. Kahn 拓扑排序 —— 顺便判环：输出顶点数 < n 就直接报错（AOE 网必须是 DAG）
3. 按拓扑序正推 ve：ve[v] = max(ve[v], ve[u] + w)        对每条出边
4. 按逆拓扑序逆推 vl：vl[u] = min(vl[u], vl[v] - w)      对每条出边
   （初值：T = max(ve[*])，所有 vl 置为 T；汇点无出边，自然保持 T）
5. 扫一遍所有活动，算 e = ve[u]，l = vl[v] - w，d = l - e
   d == 0 的活动即关键活动；在"关键子图"（只保留 d==0 的边）上从源点 DFS 即可枚举全部关键路径
```

几个实现细节：

- **T 取 `max(ve[*])` 而不是 `ve[唯一汇点]`**：这样多汇点的情况自动正确（每个汇点的 vl 都是 T）。
  有非负权时 max 必然在某个汇点取到。
- **源点不一定是 0 号点**：找入度为 0 的顶点；若有多个源点，说明工程有多个起点，应加一个
  权为 0 的虚拟源点连向它们，否则 ve 的语义会错。
- **枚举关键路径**：关键子图仍是 DAG，从源点沿 `d == 0` 的边走，走到没有关键出边的顶点就输出一条。
  注意关键活动可能组成"分支"，所以路径条数可能 > 1，别只打印第一条。
- **别用 Dijkstra**：关键路径要的是**最长**路，Dijkstra 求的是最短路，二者完全相反。
  DAG 上求最长路不需要任何高级算法，拓扑序 DP 就是 O(V+E)。

## ⑤ 复杂度小结

| 步骤 | 时间 | 空间 | 说明 |
| --- | --- | --- | --- |
| 统计入度 + 拓扑排序（Kahn） | O(V + E) | O(V) | 队列 + 入度数组 |
| 正推 ve | O(V + E) | O(V) | 每条边被"推送"一次 |
| 逆推 vl | O(V + E) | O(V) | 每条边被"拉取"一次 |
| 扫活动算 e/l/d | O(E) | O(E) | 同时得到关键活动集合 |
| 枚举全部关键路径（DFS） | O(K · L)，K = 路径条数，L = 路径长度 | O(V) 递归栈 | 路径多时输出量本身很大 |
| **合计（不含枚举）** | **O(V + E)** | **O(V + E)** | 与拓扑排序同阶，已达下界 |
| 对比：DAG 上用 Dijkstra 求最长路 | O(E log V) | O(V) | 能做但没必要，且易写错 |

## ⑥ 常见易错点

1. **把关键路径当最短路求**。它是**最长**路径：ve 递推里是 `max` 不是 `min`，这是全篇最核心的一处。
2. **正推/逆推顺序反了**。`ve` 必须按拓扑序（前驱先算），`vl` 必须按逆拓扑序（后继先算）。
   顺序错了不会报错，只会静默出错值。
3. **`vl` 初值给成 INF**。必须是 `ve[汇点]`（或 `max(ve[*])`），否则逆推出来全是 INF。
4. **忘记判环**。图有环时拓扑序不完整，`ve` 里剩下的顶点还是 0，最后算出的"工期"毫无意义。
   一定要先检查"输出顶点数 == n"。
5. **混淆事件时间（ve/vl）与活动时间（e/l）**。`e` 取**起点**的 `ve`，`l` 取**终点**的 `vl` 减权；
   写反成 `ve[j]`、`vl[i]-w` 是高频错误。
6. **`d = e - l` 算反**，导致所有余量为负、找不到关键活动。定义是 `d = l - e ≥ 0`。
7. **只输出一条关键路径**。多条关键路径是常态（如"两条并行等长支路"的经典图），
   应当枚举或至少报告条数，否则"缩短工期"的建议会漏掉一半。
8. **以为缩短任意关键活动都能省时间**。缩到与次长路径等长后就卡住了，再多缩也没用（见练习 3）。
9. **多源点/多汇点直接当单源点处理**。多个入度为 0 的顶点若不接虚拟源点，`ve` 会各自从 0 起算，
   看起来"并行"，实际漏掉了它们之间的先后约束（如果存在的话）；多汇点则要用 `max(ve[*])` 定 T。
10. **有顶点从源点不可达**。这些点的 `ve` 全是 0、`vl` 是 T，会污染结果表，也不能算进工期。
    实践中应先做一次可达性检查（本仓库代码里 `unreachableFrom` 就是干这个的）。

   `a1: v1→v2 (3)`、`a2: v1→v3 (2)`、`a3: v2→v4 (2)`、`a4: v2→v5 (3)`、
   `a5: v3→v4 (4)`、`a6: v3→v6 (3)`、`a7: v4→v6 (2)`、`a8: v5→v6 (1)`。
   手算全部 `ve`、`vl`、每项活动的 `e/l/d`，指出关键活动、关键路径与最短工期。
2. 承上：写出源点到汇点的**所有**路径及其长度，验证"最长的那条"就是第 1 题的关键路径。

   观察总工期。解释这两组结果为什么不同。
