# 查找：顺序查找、折半查找与散列表

> 学习路线第 8 站。查找是"用存储换时间"最典型的主题：顺序查找是基线，折半查找靠有序性换速度，散列靠函数直接换常数级。

## 一、基本概念与术语表

| 术语 | 含义 |
| --- | --- |
| 查找表 | 由同一类型记录构成的集合，是被查找的对象 |
| 关键字（Key） | 记录中能唯一标识该记录的数据项值 |
| 查找成功 / 失败 | 表中存在 / 不存在关键字等于给定值的记录 |
| ASL | 平均查找长度：ASL = Σ Pi·Ci，Pi 为查找第 i 个记录的概率，Ci 为比较次数 |
| 静态 / 动态查找表 | 只查找；查找同时插入或删除。BST/散列属动态查找结构 |
| 装填因子 α | 散列表：α = 表中记录数 n / 表长 m，决定冲突概率 |
| 哨兵 | 顺序查找时在表端放一个待查值副本，省去每次边界判断 |

## 二、核心性质与结论

1. **顺序查找** ASL：成功 (n+1)/2，失败 n+1（含哨兵判断）。无任何前提要求。
2. **折半查找**：n 个元素成功查找最多比较 ⌈log₂(n+1)⌉ 次；ASL ≈ log₂(n+1) − 1。**前提：顺序存储 + 有序**。判定树是一棵平衡二叉树，失败结点共 n+1 个，是外部路径长度分析的经典模型。
3. 折半查找**不适用于链式存储**：链表无法 O(1) 定位中点。
4. **散列表**：理想情况查找 O(1)，但 ASL 与 α 有关而与 n 无直接关系。**散列不能保证有序遍历，也不支持范围查询**——这是它与 BST/折半的本质取舍。
5. 除留余数法 p = key mod m 的经验取值：m 取**不超过表长的最大素数**，可减少冲突聚集。
6. 平均情况下**链地址法 ASL 优于开放定址法**：开放定址会因"堆积（聚集）"产生非同义词冲突；链地址删除也更容易（直接摘链），而开放定址删除必须做**惰性删除**（打删除标记），否则会截断探测路径。

### 折半查找判定树推导（n=7 为例）

mid = ⌊(low+high)/2⌋：

```
            4
          /   \
         2     6
        / \   / \
       1   3 5   7
```

第 1 层比较 1 次的有 1 个元素，第 2 层 2 次的有 2 个，第 3 层 3 次的有 4 个：
ASL成功 = (1×1 + 2×2 + 3×4)/7 = 17/7 ≈ 2.43。

## 三、存储结构

| 方面 | 顺序表（折半用） | 链表 | 散列表 |
| --- | --- | --- | --- |
| 折半查找 | ✔ O(log n) | ✘（无法取中点） | — |
| 插入删除代价 | O(n)（要搬移） | O(1) 定位后 | 冲突处理决定 |
| 是否有序 | 必须有序 | 任意 | 无序 |
| 范围查询 | ✔ 天然支持 | 需排序 | ✘ |

```cpp
// 顺序表（下标 1..n 存数据，0 作哨兵）
struct SeqList {
    int data[1024];
    int length;                 // 实际元素个数
};

// 散列表：开放定址（线性探测）版
struct HashTable {
    enum State { EMPTY, USED, DELETED };   // EMPTY 才能终止探测，DELETED 是墓碑
    int key[17];
    State state[17];
    int m = 17;                 // 表长取素数
};

// 散列表：链地址（拉链法）版
struct Node { int key; Node* next; };
struct ChainHash {
    Node* bucket[13];           // 桶头指针数组
    int m = 13;
};
```

## 四、核心操作实现思路

### 1. 顺序查找（带哨兵）

把待查值放进 `data[0]`，从 `length` 向下比较，循环条件只剩 `data[i] != key` 一个判断；`i == 0` 即失败。省一半边界判断是它的工程价值。

### 2. 折半查找

`low=1, high=length`；`mid=(low+high)/2`；等于返回，小于令 `high=mid-1`，大于令 `low=mid+1`。循环条件 `low <= high`。两个易漏细节：

- 用 `low + (high-low)/2` 防大数相加溢出（C++ int 也适用，习惯问题）；
- 失败时返回 0（或 -1），不要返回 mid。

### 3. 散列 — 插入与查找（开放定址）

```
h(key) = key % m
查找：从 h(key) 起线性探测 (h+d) mod m；
      遇 EMPTY → 失败（停止，不能越过 EMPTY）；
      遇 key 相等 → 成功；
      遇 DELETED → 继续探测（墓碑后面可能有目标）。
插入：先按查找规则确认不存在，再把第一个 DELETED 或 EMPTY 位置填入。
```

**关键规则**：探测遇到 EMPTY 才能断定失败；遇到 DELETED 必须继续——直接在墓碑处停会漏查后来插进更远位置的同义词。

### 4. 散列 — 链地址法

`bucket[h]` 串单链表，头插法 O(1) 插入；查找遍历对应桶；删除摘链 free。ASL成功 = 各桶内位置平均值，ASL失败 = 桶链长 + 1（含空桶那次比较）。

## 五、复杂度小结

| 方法 | 查找成功 | 查找失败 | 插入 | 删除 | 前提 |
| --- | --- | --- | --- | --- | --- |
| 顺序查找 | O(n)，ASL=(n+1)/2 | O(n+1) | O(1) 尾插 | O(n) | 无 |
| 折半查找 | O(log n)，ASL≈log₂(n+1)−1 | O(log n) | O(n) | O(n) | 顺序存储且有序 |
| 散列·开放定址 | O(1/（1−α）) | 同左 | O(1) 均摊 | O(1)（惰性） | α<1 |
| 散列·链地址 | O(1+α) | O(1+α) | O(1) | O(1) | 无（α 可 >1） |

α=0.75 时开放定址线性探测成功 ASL ≈ ½(1 + 1/(1−α)) ≈ 2.5，链地址 ≈ 1 + α/2 ≈ 1.375。

## 六、常见易错点

1. 折半查找循环写成 `while (low < high)`——最后一个元素查不到，应为 `low <= high`。
2. 折半要求"顺序存储"，对链表做折半是经典错误选项；同时"有序但链式"也不能折半。
3. 判定树 mid 取整方式（⌊⌋ 或 ⌈⌉）不同，判定树形状不同，但 ASL 同阶；答题要前后一致。
4. 顺序查找的哨兵是 `data[0]`，比较方向从 n 到 1；方向写反哨兵就失效。
5. 散列失败查找不是"比较到桶尾"：开放定址遇 EMPTY 即停；链地址要数空桶那一次比较。
6. 删除开放定址表中的元素直接置 EMPTY 会截断探测链，必须打 DELETED 标记（墓碑）。
7. 除留余数法 m 取偶数或 2 的幂会加剧冲突；经验做法是取 ≤ 表长的最大素数。
8. "散列查找 O(1)"只在 α 小且哈希函数均匀时成立；最坏情况（全部同义词）链地址退化 O(n)。
9. 折半查找插入/删除是 O(n)，"折半适合频繁增删的表"是错误说法——动态场景用 BST/散列。
10. 计算散列 ASL 成功时，分母是元素个数 n；失败时分母是哈希函数可能取值的个数（即 m 或 p），不要混用。
