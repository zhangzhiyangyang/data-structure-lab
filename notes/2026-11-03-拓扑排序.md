# 拓扑排序（Topological Sort）—— AOV 网上的排序

> 对应课程第 27 期。一句话：拓扑排序就是把一个**有向无环图（DAG）**的顶点排成一列，
> 保证每条边 `u → v` 里 u 都排在 v 的前面。它不是"比较排序"，而是一种**把偏序变成全序**的方法。

## ① 基本概念与术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| AOV 网（Activity On Vertex） | 顶点表示活动（任务）、有向边表示"先后依赖"的有向图 | 工程排课、编译依赖都是 AOV 网的例子 |
| DAG | 有向无环图（Directed Acyclic Graph） | **拓扑序列存在 ⇔ 图是 DAG**，这是全篇最重要的定理 |
| 前驱 / 后继 | 边 `u → v` 中，u 是 v 的前驱，v 是 u 的后继 | 直接前驱也叫"入边来源" |
| 入度 indegree | 指向该顶点的边数，即"还有几个前驱没完成" | Kahn 算法的核心量 |
| 出度 outdegree | 从该顶点指出的边数 | DFS 法里用于递归 |
| 偏序 | 只要求部分元素有先后关系（图里有边才有） | AOV 网表达的是偏序 |
| 全序 | 任意两个元素都可比（一条确定的线） | 拓扑序 = 从偏序造出的一条全序 |
| 拓扑序列 | 顶点的一个排列，满足每条边 `u → v` 都有 u 在 v 前 | **一般不唯一** |

## ② 核心性质 / 定理

1. **存在性定理**：有向图 G 存在拓扑序列 ⇔ G 中没有环。
   - 推广：G 的拓扑序包含**全部** n 个顶点 ⇔ G 无环。Kahn 算法正好利用这一点判环。
   - 直观证明：若图无环，入度最小的顶点（入度为 0）一定存在，删掉它剩下的图仍无环，
     归纳下去每次都能选出顶点；反之若有环，环上顶点互相等待，入度永远降不到 0。
2. **不唯一性**：拓扑序一般不唯一。所有入度为 0 的顶点在"当前这一步"都可以选。
   - 特例：若每一步候选集合恰好只有 1 个顶点，拓扑序才唯一。
3. **DFS 性质**：对 DAG 做 DFS，按**退出（finish）时间的逆序**排列顶点，就是一个拓扑序列。
   - 原因：边 `u → v` 只能是树边/前进边/横向边（DAG 里没有回边），
     无论哪种情况 u 都比 v **晚退出**，逆序后 u 排在 v 前。
4. **排序复杂度**：无论 Kahn 还是 DFS 法，时间都是 O(V + E)——线性于"顶点数 + 边数"，
   这是能期望的下限（每条边至少要看一次）。
5. 拓扑序可以反过来用：把 DAG 的边全部反向后求拓扑序，得到的是"逆拓扑序"；
   而"最短/最长路 DP"（如关键路径、AOE 网络）都要**按拓扑序**处理顶点——这是它的最大用途。

## ③ 存储结构

拓扑排序只关心"谁能到谁"，边不带权，**邻接表是最优选择**：
遍历某顶点的后继只需 O(出度)；邻接矩阵求某顶点后继要 O(V)，n 个顶点就是 O(V²)，浪费。

```cpp
// 邻接表存 DAG：顶点用编号 0..n-1，边表存后继
struct Graph {
    int n;                            // 顶点数
    vector<vector<int>> adj;          // adj[u] = u 的所有后继（出边表）

    explicit Graph(int n_) : n(n_), adj(n_) {}

    void addEdge(int u, int v) {      // 加一条有向边 u → v，O(1)
        adj[u].push_back(v);
    }
};
```

两种存储的对比：

| | 邻接表（推荐） | 邻接矩阵 |
| --- | --- | --- |
| 求全部后继 | O(出度) | O(V) |
| 求全部入度（建表时） | O(V + E) | O(V²) |
| 空间 | O(V + E) | O(V²) |
| 适用场景 | 稀疏图（AOV 网几乎都是稀疏的） | 稠密图 |

## ④ 核心操作的实现思路

### Kahn 算法（BFS 思想，最常用，顺带判环）

1. 扫一遍所有边，统计每个顶点的**入度** `indeg[v]`。
2. 把所有入度为 0 的顶点放进队列（它们没有前驱，可以立刻"开工"）。
3. 依次出队顶点 u，记入结果序列；然后把 u 的每个后继 v 的入度 **减 1**；
   若 `indeg[v]` 变成 0，就把 v 入队。
4. 队列空了之后：若输出的顶点数 **< n**，说明剩下的顶点入度永远到不了 0，
   它们构成环 → **图有环，无拓扑序**；否则结果序列就是一组合法的拓扑序。

正确性：每次出队的顶点入度为 0，意味着它的所有前驱都已输出，所以它当前排在后面是安全的。

### DFS 法（逆拓扑序）

对每个未访问顶点调用 DFS；在 DFS 从某个顶点**返回之前**把该顶点压栈。
全部结束后依次弹栈输出，得到的序列就是拓扑序（②-3 的性质）。
注意：普通 DFS 法假设图无环；要判环需给顶点染色（0 未访问 / 1 在递归栈中 / 2 已完成），
遇到"访问到染色为 1 的顶点"即发现环。

## ⑤ 复杂度小结

| 算法 | 时间 | 空间 | 能否判环 | 备注 |
| --- | --- | --- | --- | --- |
| Kahn（队列） | O(V + E) | O(V)（入度数组 + 队列） | 能（输出顶点数 < n 即有环） | 最常用，序列自前向后生成 |
| Kahn（栈代替队列） | O(V + E) | O(V) | 能 | 结果不同但同样合法 |
| DFS + 逆序 | O(V + E) | O(V)（递归栈/颜色数组） | 需加三色标记才能判环 | 序列自后向前生成（逆拓扑） |
| 退化对比：反复暴力找入度 0 顶点 | O(V²) | O(V) | 能 | 教科书简写法，仅适合小图 |

## ⑥ 常见易错点

1. **建图方向搞反**：任务 u 必须在 v 之前完成，是加边 `u → v`（u 指向 v）。
   反了之后求出来的是逆拓扑序，后面做关键路径 DP 会全错。
2. **统计入度时扫错方向**：`indeg[v]++` 是对**边表里的 v** 加，不是对 `adj[u]` 的下标 u 加。
3. **有环时忘记检查**：只打印序列不数个数，环图会"悄悄"输出前半段，看似成功。
   正确做法是输出个数与 n 比对，或直接报告"存在环"。
4. **入度减到 0 才入队**：减 1 之后要先判断 `indeg[v] == 0` 再 push，
   把"还没到 0"的顶点也入队会重复输出。
5. **拓扑序不唯一是常态**：队列和栈给出的序列都合法，考试手算时不同工具得到不同序列，别慌——
   判断标准是"每条边前驱都在后继前面"，而不是背答案。
6. **DFS 法输出方向**：压栈发生在**递归返回时**，最终是**逆序弹栈**输出；
   写成访问时直接输出会得到反的序列。
7. **重复边**：同一对顶点加两次边会让入度多算，Kahn 算法里该顶点永远进不了队列。
   邻接表不自动去重，加边前要保证输入无重复。
8. **自环**：`u → u` 使 u 的入度永远 ≥ 1，自环即环，算法会正确报告有环，不要"特判掉"。
