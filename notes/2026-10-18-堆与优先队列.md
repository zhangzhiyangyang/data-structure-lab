# 堆与优先队列

> 学习笔记 · 2026-10-18 · 配套代码：[`code/2026-10-18-heap_priority_queue.cpp`](../code/2026-10-18-heap_priority_queue.cpp)

## 一、基本概念与术语

**堆（Heap）** 是满足下面两个条件的序列 `{k₁, k₂, …, kₙ}`：

1. **结构性质**：把序列按层序放进一棵完全二叉树后，得到的是一棵**完全二叉树**（除最后一层外每层都满，最后一层的结点全部靠左连续）；
2. **堆序性质**：每个结点都不大于（或不小于）它的所有孩子。

只有第 1 条时它只是一棵完全二叉树；只有第 2 条时它可能长成一条链，无法用数组高效存储。两条一起，才让「数组下标」与「树的父子关系」直接对应，从而不需要指针。

| 术语 | 含义 |
| --- | --- |
| 大顶堆（最大堆） | 每个结点 ≥ 其孩子，堆顶是整个集合的**最大值** |
| 小顶堆（最小堆） | 每个结点 ≤ 其孩子，堆顶是整个集合的**最小值** |
| 堆序性 | 父结点与孩子的偏序关系，只约束**纵向**路径，不约束兄弟之间 |
| 上浮（sift-up / swim） | 新元素放到数组末尾，与父结点比较并逐层上移 |
| 下沉（sift-down / sink） | 元素与**较大（较小）的那个孩子**交换并逐层下移 |
| 堆化（heapify） | 让某个子树重新满足堆序性的过程，即一次下沉 |
| 建堆（build-heap） | 从无序数组构造堆，自底向上对每个非叶结点下沉一次，`O(n)` |
| 优先队列 | 只支持「插入」与「取出最优先元素」的抽象数据类型，堆是其标准实现 |
| 对顶堆 | 一个大顶堆 + 一个小顶堆，两者顶部分割数据的中位数 |
| d 叉堆 | 每个结点有 d 个孩子的堆，下标关系为 `d·i+1 … d·i+d` |

**堆与优先队列的关系**：堆是**数据结构**（怎么存），优先队列是**抽象数据类型**（要什么操作）。优先队列可以用有序数组、无序数组、BST、堆等多种结构实现，其中堆在「插入 + 取极值」这组操作上综合代价最低，所以工业界的优先队列基本都是堆。

## 二、核心性质与定理

### 1. 完全二叉树 ⟹ 数组下标就是父子关系

对 n 个结点的完全二叉树按层序从 0 开始编号，则对任意下标 i：

| 关系 | 0-based（C/C++ 数组） | 1-based（教材常用） |
| --- | --- | --- |
| 父结点 | `(i-1)/2`（i > 0） | `⌊i/2⌋`（i > 1） |
| 左孩子 | `2i+1` | `2i` |
| 右孩子 | `2i+2` | `2i+1` |
| 最后一个非叶结点 | `n/2 - 1` | `⌊n/2⌋` |
| 第一个叶子结点 | `n/2` | `⌊n/2⌋+1` |

这套关系成立的前提是**完全二叉树**——结点编号连续、中间不空。所以堆的插入必须「追加到末尾」，删除只能「删堆顶并用末尾元素补位」，任何在中间挖洞的操作都会破坏下标映射。

### 2. n 个结点的堆高度为 ⌊log₂n⌋

完全二叉树第 k 层（根为第 0 层）最多 `2^k` 个结点，前 h 层共 `2^(h+1) - 1` 个结点。由

```
2^h - 1 < n ≤ 2^(h+1) - 1
```

取对数得 `h = ⌊log₂n⌋`（h 为边数，层数为 `⌊log₂n⌋ + 1`）。这是堆所有操作都是 `O(log n)` 的根源：上浮/下沉最多走完整条根到叶的路径。

### 3. 自底向上建堆是 O(n)，不是 O(n log n)

这是堆最容易被低估的一点。逐个插入建堆确实是 `O(n log n)`，但「从最后一个非叶结点往前，对每个结点下沉一次」的总代价是线性的。

设高度为 h，第 k 层有 `2^k` 个结点，该层结点下沉最多 `h-k` 层：

```
T(n) = Σ(k=0 → h-1) 2^k · (h - k)
```

令 `j = h - k`，则

```
T(n) = Σ(j=1 → h) 2^(h-j) · j = 2^h · Σ(j=1 → h) j/2^j
```

而 `Σ(j≥1) j/2^j = 2`（可由 `Σ x^j = 1/(1-x)` 求导令 x=1/2 得到），于是

```
T(n) < 2^h · 2 = 2^(h+1) ≤ 2n  ⟹  T(n) = O(n)
```

**直觉解释**：绝大多数结点都在底层，而底层结点本身几乎不用下沉（叶子根本不下沉）。代价高的上层结点数量极少。所以「大部分工作由大量廉价结点完成」，总和收敛。

对比：逐个插入时，第 i 次插入最多上浮 `log i` 层，`Σ log i = O(n log n)`——那才是「让每个元素都走完整条路径」。

### 4. 堆只保证偏序，不保证全序

| 问题 | 大顶堆 | 二叉搜索树 |
| --- | --- | --- |
| 取最大值 | `O(1)`（堆顶） | `O(log n)`（最右结点） |
| 取最小值 | `O(n)`（必须扫叶子） | `O(log n)`（最左结点） |
| 查找任意值 | `O(n)` | `O(log n)` |
| 插入 | `O(log n)`，常数小、无旋转 | `O(log n)`，可能需旋转 |
| 顺序遍历 | 不支持（数组非有序） | 中序即升序 |
| 存储 | 数组，无指针，缓存友好 | 链式，指针开销 |

**结论**：需要「反复取极值」用堆；需要「按值查找、有序遍历、范围查询」用 BST。堆的数组布局连续访问，实际常数远小于 BST，这也是 `std::priority_queue` 比 `std::set` 快的原因。

### 5. 大顶堆升序、小顶堆降序

堆排序的做法是：建大顶堆 → 把堆顶（当前最大值）与末尾交换 → 堆的有效范围减一 → 对新堆顶下沉。

为什么大顶堆得到**升序**：每轮都把当前最大值「扔」到数组末尾并固定下来，末尾从后往前依次填的是最大值、次大值、……，所以最终数组从前到后是升序。**想升序就建大顶堆**，这个方向不要记反。

### 6. 求最大 K 个元素要用小顶堆

反直觉但正确：维护一个容量为 k 的**小顶堆**，堆里存「目前已见过的最大 k 个」，堆顶是这 k 个里最小的，也就是**淘汰线**。新元素只要比堆顶大，就替换堆顶。

- 用小顶堆：`O(n log k)`，额外空间 `O(k)`；
- 用大顶堆存全部再弹 k 次：`O(n + k log n)`，空间 `O(n)`，n 很大时不可行。

## 三、存储结构

### 顺序存储（堆的唯一实用选择）

```cpp
// 大顶堆：用动态数组存完全二叉树的层序序列
typedef struct {
    int* data;      // 数据区，下标 0 对应根
    int  size;      // 当前元素个数
    int  capacity;  // 容量上限
} MaxHeap;

// 教材风格（1-based，data[0] 空置不用）
typedef struct {
    int data[MaxSize];  // data[1..n] 存放元素，data[0] 可作哨兵
    int length;
} SqHeap;
```

`data[0]` 空置的写法能让 `父 = i/2` 更整齐，代价是浪费一个单元；C++ 实战用 0-based，与 `std::vector` 天然对齐。

### 顺序 vs 链式对比

| 对比项 | 顺序存储（数组） | 链式存储（二叉链表） |
| --- | --- | --- |
| 结构要求 | 必须是完全二叉树（堆天然满足） | 任意二叉树 |
| 空间开销 | 恰好 n 个元素，无指针 | 每结点 2~3 个指针，额外 16~24 字节 |
| 定位父子 | 下标算术，`O(1)` 且无访存 | 需解引用指针 |
| 缓存友好性 | 高（连续内存，预取有效） | 低（随机跳转） |
| 插入 | 尾部追加，可能扩容拷贝 | 找到插入位置挂链 |
| 删除堆顶 | 末尾元素补位后下沉 | 需维护尾指针 + 双亲指针 |
| 实现难度 | 极简 | 需处理指针失效 |

**结论**：堆的形态被「完全二叉树」锁死，顺序存储零浪费，所以堆一律用数组。链式堆只在教学对比中出现。

## 四、核心操作的实现思路

### 1. 下沉（sift-down）：堆的灵魂

```
siftDown(i):
    loop:
        largest ← i
        if 左孩子存在 且 a[左] > a[largest]: largest ← 左
        if 右孩子存在 且 a[右] > a[largest]: largest ← 右
        if largest == i: 结束            // 已满足堆序
        交换 a[i] 与 a[largest]
        i ← largest
```

关键细节：必须**两个孩子都比较一遍**，挑出三者中最大的再交换。只跟「左孩子」或「默认较大的那个」比较，会把较小的父结点换下去后又压在更大的孩子上，堆序仍然被破坏。

```cpp
// 对 [0, n) 范围内的下标 i 做下沉；cmp 用于统计比较次数
void siftDown(std::vector<int>& a, std::size_t i, std::size_t n, long long& cmp) {
    while (true) {
        std::size_t largest = i;
        std::size_t l = 2 * i + 1, r = 2 * i + 2;
        if (l < n) { ++cmp; if (a[l] > a[largest]) largest = l; }
        if (r < n) { ++cmp; if (a[r] > a[largest]) largest = r; }
        if (largest == i) return;
        std::swap(a[i], a[largest]);
        i = largest;
    }
}
```

### 2. 上浮（sift-up）：插入专用

新元素只能放在数组末尾（保持完全二叉树），然后与父结点比较、必要时交换，一路上浮到合适位置。上浮路径唯一，每层只需 1 次比较，比下沉便宜。

```cpp
void siftUp(std::vector<int>& a, std::size_t i) {
    while (i > 0) {
        std::size_t p = (i - 1) / 2;
        if (a[p] >= a[i]) break;
        std::swap(a[p], a[i]);
        i = p;
    }
}
```

### 3. 插入 / 删除堆顶

| 操作 | 步骤 | 代价 |
| --- | --- | --- |
| 插入 x | 末尾追加 x → 从末尾上浮 | `O(log n)` |
| 删除堆顶 | 取走 `a[0]` → 末尾元素搬到 `a[0]` → 从根下沉 | `O(log n)` |
| 取堆顶 | 直接返回 `a[0]` | `O(1)` |
| 删除任意元素 | 需额外维护「元素 → 下标」映射，末尾补位后**上浮或下沉二选一** | `O(log n)` |

删除堆顶为什么用「末尾补位」而不是「把较大孩子提上来」：后者会留下一个洞，破坏完全二叉树性质；末尾补位后结构仍是完全二叉树，只需一次下沉修复堆序。

删除任意元素时，补位上来的元素可能比原位置大也可能小，所以**两个方向都要试**（先试上浮，若不成功再下沉，或直接比较与父结点）。

### 4. 建堆：两种方式

| 方式 | 做法 | 复杂度 | 比较次数（n=1000 实测） |
| --- | --- | --- | --- |
| 逐个插入 | 从空堆开始，每次 push 到末尾再上浮 | 最坏 `O(n log n)` | 约 8.0n（升序输入，最坏） |
| 自底向上 | 从 `n/2-1` 到 0 依次下沉 | `O(n)` | 约 2.0n（与输入顺序无关） |

> 实测补充：同一份随机数据下，逐个插入只有约 2.3n——因为新元素上浮一两层就会停下。**8.0n 是最坏情形（升序输入，每个新元素都浮到根），不是平均情形**。工程上讨论建堆复杂度时说的 `O(n)` 与 `O(n log n)`，比的正是这两个上界。

```cpp
// 自底向上建堆：叶子本身已是合法堆，只需处理非叶结点，且必须从后往前
void buildHeap(std::vector<int>& a) {
    long long cmp = 0;                                 // 比较次数计数器，仅用于统计
    for (std::size_t i = a.size() / 2; i-- > 0; ) {    // i 从 n/2-1 递减到 0
        siftDown(a, i, a.size(), cmp);
    }
}
```

**为什么必须从后往前**：下沉要求「左右子树已经是堆」。从后往前处理时，下标 i 的孩子下标都大于 i，已经被处理过，所以子树合法。若从前往后，孩子还没修好就下沉父结点，结果不可靠。

### 5. 堆排序

```
1. 对 a[0..n-1] 建大顶堆                        O(n)
2. for end = n down to 2:
       swap(a[0], a[end-1])                     // 当前最大值归位
       siftDown(a, 0, end-1)                    // 有效范围缩小后修复堆顶
```

总代价 `O(n) + n·O(log n) = O(n log n)`，原地，额外空间 `O(1)`。

**不稳定性**：交换 `a[0]` 与 `a[end-1]` 是长距离交换，会把相等元素的相对次序打乱。例：`[2a, 2b, 1]` 建堆后 `[2a, 2b, 1]`，第一轮 `2a` 与 `1` 交换得 `[1, 2b, 2a]`，`2a` 与 `2b` 的次序已经反了。

### 6. 优先队列的两个经典应用

**应用一：任务调度**。把任务按优先级放进优先队列，每次取优先级最高的执行。优先级相同时用一个稳定的次序键（如任务名）打破平局，否则输出不确定、无法测试。

**应用二：数据流中位数（对顶堆）**。维护两个堆：

```
low  : 大顶堆，存较小的一半，堆顶 = 这一半的最大值
high : 小顶堆，存较大的一半，堆顶 = 这一半的最小值
不变式：low.size() == high.size()  或  low.size() == high.size() + 1
```

插入时要同时恢复「大小关系」和「数量关系」：先按与 `low.top()` 的比较决定进哪个堆，再把超出的大小差搬一个元素到另一个堆。中位数：

- 元素个数为奇数：`low.top()`；
- 元素个数为偶数：`(low.top() + high.top()) / 2.0`。

这个结构插入 `O(log n)`、查询中位数 `O(1)`，是「动态第 k 大」类问题的通用套路。

## 五、复杂度小结

| 操作 | 时间复杂度 | 空间 | 说明 |
| --- | --- | --- | --- |
| 取堆顶 top | `O(1)` | `O(1)` | 直接返回 `a[0]` |
| 插入 push | `O(log n)` | 均摊 `O(1)` | 上浮，最坏走满树高 |
| 删除堆顶 pop | `O(log n)` | `O(1)` | 末尾补位 + 下沉 |
| 删除任意元素 | `O(log n)` | `O(n)` 额外索引 | 需维护位置映射 |
| 修改某元素优先级 | `O(log n)` | `O(n)` 额外索引 | 上浮或下沉 |
| 自底向上建堆 | `O(n)` | `O(1)` | 优于逐个插入 |
| 逐个插入建堆 | `O(n log n)` | `O(1)` | 每次上浮 |
| 堆排序 | `O(n log n)` | `O(1)` | 原地、不稳定 |
| 查找任意值 | `O(n)` | `O(1)` | 堆无序，只能遍历 |
| Top-K（最大 k 个） | `O(n log k)` | `O(k)` | 维护 k 大小的小顶堆 |
| 数据流中位数 | 插入 `O(log n)` | `O(n)` | 对顶堆 |

注：`std::priority_queue` 底层是 `std::vector` + `std::push_heap/pop_heap`，`make_heap` 就是自底向上建堆。

## 六、常见易错点

1. **0-based 与 1-based 下标公式混用**。写成 `2*i` / `2*i+1` 却用 0-based 数组，根的孩子会算成 `0` 和 `1`，第一个元素与自己比较，堆立刻错乱。0-based 必须是 `2i+1` / `2i+2`。
2. **下沉时只看一个孩子**。必须比较「父、左孩子、右孩子」三者取最大，否则会出现父结点小于某个孩子却停止下沉的情况。
3. **建堆循环边界写错**。应从 `n/2 - 1` 开始（0-based），写成 `n/2` 会漏掉下标 `n/2-1` 这个非叶结点；写成 `n-1` 则是浪费（叶子无需下沉）。
4. **建堆方向写成从前往后**。下沉依赖子树已合法，必须从后往前；从前往后结果不保证是堆。
5. **以为建堆后数组有序**。建堆只保证堆序，`a[1]` 与 `a[2]` 的大小关系是任意的。要全部有序必须跑完堆排序。
6. **插入用下沉、删除用上浮**。插入位置在末尾，只能往上修；删除堆顶后补位元素在根部，只能往下修。反了就是做无用功。
7. **`std::priority_queue` 默认是大顶堆**。要小顶堆必须写 `priority_queue<int, vector<int>, greater<int>>`，并且 `#include <functional>`。
8. **Top-K 求「最大 K 个」用了大顶堆**。大顶堆堆顶是最大值，无法充当淘汰线；求最大 K 个要用**小顶堆**，求最小 K 个才用大顶堆。
9. **堆排序误认为稳定**。远距离交换必然破坏相等元素次序；要稳定排序用归并。
10. **优先队列里放结构体忘了给全序比较**。只比较优先级时，相同优先级的元素出队顺序依赖堆的内部实现，不可预测，测试会随机挂。补一个次序键即可确定化。
11. **对顶堆只平衡数量、不校验大小关系**。必须保证 `low` 中所有元素 ≤ `high` 中所有元素，否则中位数取到的是两个不相邻的中间值。

## 七、练习题

> 答案见配套代码 `code/2026-10-18-heap_priority_queue.cpp`，每道题对应一个独立函数。

**练习 1（判堆）** 给定一个整数数组，判断它是否是大顶堆。要求 `O(n)` 时间、`O(1)` 额外空间。提示：只需检查每个非叶结点 `i` 与其孩子 `2i+1`、`2i+2` 的关系，不必真的建树。

**练习 2（Top-K）** 从 n 个整数中找出最大的 k 个（k ≪ n），并说明为什么用**小顶堆**而不是大顶堆。给出时间与空间复杂度；若 n = 10⁶、k = 10，估算需要多少次「堆内比较」量级。
