# B 树与 B+ 树（课程 37~39）

> 前面学的 BST / AVL / 红黑树都是「内存里」的结构：一个结点只装一个关键字，跳一次指针的代价近乎为零，于是我们拼命压低树高。可一旦数据量大到必须存磁盘，**访问一个结点 = 一次磁盘 I/O（几毫秒到几十毫秒）**，这时唯一值得优化的指标变成「要读几个结点」。B 树的做法很直接：把一个结点放大成一个磁盘块（4KB~16KB），里面塞几百个关键字，树高从 `log₂n` 掉到 `log_m n` —— 10 亿条记录只要 4 层。这就是数据库索引与文件系统都用 B/B+ 树的根本原因。

## 一、基本概念与术语表

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 阶 | order `m` | 一个结点**最多**拥有的子树棵数；也即最多 `m-1` 个关键字 |
| 最小度 | minimum degree `t` | CLRS 口径：每个结点至少 `t-1`、至多 `2t-1` 个关键字，故 `m = 2t` |
| 关键字 | key | 结点内存放的、有序排列的检索码；`n` 个关键字把区间分成 `n+1` 段 |
| 子树指针 | child pointer | `n` 个关键字对应 `n+1` 个孩子指针，`key[i]` 左子树全小于它、右子树全大于它 |
| 内部结点 | internal node | 含关键字且带孩子的结点（B+ 树中它只当索引，不存记录） |
| 叶结点 | leaf | 国内教材：不带信息的**失败结点**，全部在同一层；CLRS：最底层真正存关键字的结点 |
| 扇出 | fan-out | 一个结点平均分出的孩子数，直接决定树高 |
| 磁盘块 | disk block / page | I/O 的最小单位，B 树结点大小通常对齐到一个块 |
| 分裂 | split | 结点关键字数超上限时，中间关键字上移到父结点，剩余部分拆成两个结点 |
| 借位 / 旋转 | borrow / rotate | 删除后关键字数不足下限，向兄弟「借」一个，经父结点中转 |
| 合并 | merge | 兄弟也不够借时，与兄弟连同父结点的分隔关键字合并成一个结点 |
| 稠密索引 | dense index | B+ 树叶层为每个关键字都建一条索引项 |

## 二、核心性质与定理

### 1. `m` 阶 B 树的定义（国内教材口径，五条缺一不可）

1. 每个结点**至多** `m` 棵子树、`m-1` 个关键字。
2. 根结点若非叶，**至少 2 棵子树**（即至少 1 个关键字）。
3. 除根和叶外，每个结点**至少** `⌈m/2⌉` 棵子树，即至少 `⌈m/2⌉-1` 个关键字。
4. 所有叶结点（失败结点）**都在同一层**，不带信息。
5. 有 `k` 棵子树的非叶结点恰有 `k-1` 个关键字，且 `key[0] < key[1] < … < key[k-2]`；`key[i]` 左侧子树的所有关键字都小于 `key[i]`，右侧都大于 `key[i]`。

> 第 3 条是「平衡」的全部来源：任何结点都不会瘦到只剩一两个关键字，树才不会退化成链表。

### 2. 最小度 `t` 口径（CLRS，本笔记代码采用）

每个结点存 `n` 个关键字，满足 `t-1 ≤ n ≤ 2t-1`（根除外，根允许 `n = 0`）；内部结点有 `n+1` 个孩子。两者换算：**`m = 2t`，关键字上限 `m-1 = 2t-1`，下限 `⌈m/2⌉-1 = t-1`**。`t=3` 即 6 阶，一个结点 2~5 个关键字。

### 3. 高度上界（含推导）

**定理**：含 `n ≥ 1` 个关键字的 `m` 阶 B 树，高度 `h`（叶结点层也算一层，根为第 1 层）满足

```
h ≤ log_⌈m/2⌉ ( (n+1)/2 ) + 1
```

**推导**：

- 关键字 `n` 个，把全体键值域切成 `n+1` 段，而 B 树的每个失败结点（叶）恰好对应一段，所以**叶结点数 = n+1**。
- 反过来数叶：第 1 层 1 个结点；第 2 层至少 2 个；此后每个非叶结点至少 `⌈m/2⌉` 个孩子，故第 `i` 层（`i ≥ 2`）至少 `2·⌈m/2⌉^{i-2}` 个结点，第 `h` 层（叶层）至少 `2·⌈m/2⌉^{h-2}` 个。
- 联立：`n+1 ≥ 2·⌈m/2⌉^{h-2}`，两边取对数即得上式。

**推论（关键字数下界）**：高度为 `h` 的 `m` 阶 B 树，最少关键字数是

```
N_min(h) = 1 + 2(⌈m/2⌉-1)·(⌈m/2⌉^{h-2} + … + 1) = 2·⌈m/2⌉^{h-1} - 1
```

**推论（关键字数上界）**：每层都塞满时 `N_max(h) = m^h - 1`。

**实用估算**：设一条索引项 16 字节（8 字节键 + 8 字节指针），磁盘块 4KB → 每结点约 256 个关键字，即 `m ≈ 257`。`257³ × 256 ≈ 4.3×10⁹`，所以 **10 亿条记录只需 3 层内部结点 + 1 层叶子 = 4 次 I/O**。而同样数据量的AVL树要 `log₂(10⁹) ≈ 30` 次 I/O —— 差了一个数量级，这就是 B 树存在的意义。

### 4. B+ 树与 B 树的本质区别

| 项目 | B 树 | B+ 树 |
| --- | --- | --- |
| 记录存放位置 | 每个结点都存关键字 + 数据（或数据指针） | **只有叶子**存数据，内部结点只存索引键 |
| 关键字是否重复 | 不重复，全局唯一 | 内部结点的键是「右子树最小键」的**副本**，叶子中重复出现 |
| 叶子间链接 | 无 | 叶子按关键字升序**链成链表** |
| 查找终点 | 可能在内部结点命中，**提前结束** | 必须走到叶子，**路径长度恒定** |
| 范围查询 | 中序遍历，跨结点要回溯，效率低 | 定位起点后沿叶子链**顺序扫描** |
| 同阶下扇出 | 小（结点要放数据） | 大（内部结点只放键），树更矮 |
| 典型应用 | 文件系统目录（ext4 htree 变体）、部分内存索引 | MySQL InnoDB、Oracle、SQL Server 的聚簇/二级索引 |

> 一句话记忆：**B 树是「每个路口都可能有你要找的店」，B+ 树是「路口只有路牌，店全在最后一排，且那排店门对门连着」**。

## 三、存储结构

### 1. 从磁盘块到内存结点

B 树结点被设计成「一个磁盘块大小」。读结点 = 读一个块；在块内用二分查找定位关键字（块内是连续数组，CPU 缓存友好）。因此 B 树的性能模型是 **I/O 次数**，而不是比较次数：比较多少次几乎不影响，读几个块才是关键。

### 2. B 树结点结构体（与配套代码一致）

```cpp
// B 树结点：关键字升序存于 key，n 个关键字配 n+1 个孩子
struct Node {
    bool leaf;                 // 是否叶结点（true 时 child 为空）
    std::vector<int> key;      // key.size() 即关键字个数 n，n <= 2t-1
    std::vector<Node*> child;  // child.size() == key.size() + 1（内部结点）
};
```

### 3. B+ 树结点结构体

```cpp
// B+ 树内部结点：只存索引键，key.size() 个键配 key.size()+1 个孩子
struct InnerNode {
    std::vector<int> key;      // key[i] == 第 i+1 棵子树中的最小关键字
    std::vector<Node*> child;
};

// B+ 树叶子结点：存真正数据，并用 next 串成有序链表
struct LeafNode {
    std::vector<int> key;      // 叶子内的关键字，升序
    std::vector<int> data;     // 实际记录（示例中用与 key 对应的整型代替）
    LeafNode* next;            // 指向下一个叶子，支持范围查询顺序扫描
    LeafNode* prev;            // 可选：双向链表，便于逆序查询
};
```

两者共用一个 `Node`（带 `leaf` 标志位 + `next` 指针）在实际代码里更省事，本例即如此：

```cpp
struct Node {
    bool leaf;                              // true = 叶子结点
    std::vector<int> key;                   // 关键字（B+ 树内部结点为索引键）
    std::vector<Node*> child;               // 内部结点的孩子
    Node* next = nullptr;                   // 仅叶子使用：后继叶子
    explicit Node(bool isLeaf) : leaf(isLeaf) {}
};
```

**顺序 vs 链式对比**：结点内部用**顺序数组**（随机访问、块内二分、缓存友好），结点之间用**指针链**（避免整棵树连续存储时分裂要大搬家）。这是「块内顺序 + 块间链接」的典型混合结构，和「索引顺序表」的思路一致。

## 四、核心操作的实现思路

### 1. 查找（两条路径都是一条从根到叶的链）

- **B 树**：在结点内顺序/二分找第一个 `≥ k` 的位置 `i`；若 `key[i] == k` 命中返回；否则若叶结点则失败，非叶则下探 `child[i]`。
- **B+ 树**：内部结点只做路由（用 `upper_bound` 找到孩子下标），**必须落到叶子**才能判断是否存在；好处是查找路径长度恒定，性能可预测。

```
B 树查找 41（6 阶 t=3，每结点 2~5 个键）：
            [ 20 | 40 ]
          /      |      \
   [5|12]    [25|30|35]   [45|50]
      ↓ 40 < 41 ≤ 45 → 走第三棵子树 → 未命中，失败
```

### 2. 插入（关键是「分裂」）

1. 沿查找路径下到叶结点，在有序位置插入 `k`。
2. 若插入后关键字数 `> m-1`（CLRS：`> 2t-1`），**分裂**：
   - 取**中间**关键字 `key[mid]` 上移到父结点作为新的分隔键；
   - 左半留在原结点，右半放进新结点；
   - 父结点因此多了一个键和一个孩子，若父结点也满了，继续向上分裂。
3. 若根分裂，新建一个只含 1 个键、2 个孩子的根，**树高 +1**。这是 B 树长高的**唯一**方式。

> 两种实现风格：**预分裂**（top-down，CLRS 采用：下探时遇到满结点先拆，保证父结点永远有空位，一次下行即可完成）与**后分裂**（bottom-up：插完再回溯拆，需要记录路径）。前者不需要递归回溯，适合磁盘场景。

分裂时下标要算清楚（`t=3`，满结点 5 个键，下标 0~4）：

```
分裂前: [ 3 7 12 18 25 ]        mid = t-1 = 2 → 键 12 上移
分裂后: [ 3 7 ]  12  [ 18 25 ]   ← 左右各 2 个键，均 ≥ t-1
```

### 3. 删除（三种情况 + 借位/合并）

1. **删的关键字在叶结点**：直接删。若删后关键字数 `< ⌈m/2⌉-1`（CLRS：`< t-1`），进入「欠账」处理。
2. **在内部结点**：不能直接删（会留下窟窿，孩子没法挂）。用**前驱**（左子树最右键）或**后继**（右子树最左键）替换它，问题转化为在叶子上删那个前驱/后继，递归处理。
3. **欠账处理**（设欠账结点为 `x`，父结点为 `p`，兄弟为 `s`）：
   - **兄弟够借**（`s` 的关键字数 `> ⌈m/2⌉-1`）：**经父结点旋转** —— `p` 的分隔键下移到 `x`，`s` 的一个键上移到 `p`。注意不是直接把 `s` 的键搬给 `x`，必须保持「左小右大」。
   - **兄弟不够借**：**合并** —— `x` + `p` 的分隔键 + `s` 合成一个结点，`p` 少一个键、少一个孩子。若 `p` 因此欠账，向上继续；若根被合并空了，删掉根，**树高 -1**。

### 4. B+ 树的插入与范围查询

- **插入**：只在叶子插入；叶子溢出（`> M-1` 个键）就分裂成两个叶子，把右叶的**最小键复制**（不是移动）到父结点；父结点溢出同理，但**上移的是移动**（内部键不在别处重复）。全程保持叶子链表：`新右叶->next = 原叶->next; 原叶->next = 新右叶`。
- **范围查询 `[lo, hi]`**：从根按 `lo` 路由到叶子（`O(log_M n)` 次 I/O），然后**沿 `next` 链顺序扫描**直到某键 `> hi`（`O(k/B)` 次 I/O，`k` 为结果数）。因为叶子是连续的块，这几乎是顺序 I/O，远快于 B 树的中序回溯。

```
叶子链：[1 3] → [5 7] → [9 11] → [13 15]      （示意树，非测试数据）
查询 [4, 9]：路由到 [5 7]，扫描得 5 7，跨到 [9 11] 得 9，下一键 11 > 9 停止 → 访问 2 个叶子
```

## 五、复杂度小结

设关键字总数 `n`，阶 `m`（最小度 `t = m/2`），结点容量为一个磁盘块。

| 操作 | 时间复杂度（I/O 次数） | 块内代价 | 说明 |
| --- | --- | --- | --- |
| 查找 | `O(log_m n)` | `O(log m)` 或 `O(m)` | 每层恰好 1 次结点访问；块内二分 `O(log m)` |
| 插入 | `O(log_m n)` | 分裂 `O(m)` | 只有满结点才分裂，均摊分裂次数 `O(1)` |
| 删除 | `O(log_m n)` | 借位/合并 `O(m)` | 合并可能沿路径连锁上传，每层 1 次 |
| 范围查询（B 树） | `O(log_m n + k)`，常数大 | — | 中序要跨结点回溯 |
| 范围查询（B+ 树） | `O(log_m n + k/B)` | — | 叶子链顺序扫描，`B` 为每块记录数 |
| 空间 | `O(n)` | — | B 树每结点都存数据，扇出小；B+ 树内部结点只存键，空间利用率更高 |

| 高度对比（`n = 10⁹`） | 树高 / I/O 次数 |
| --- | --- |
| 平衡二叉树（AVL / 红黑树） | `≈ 30` |
| B 树 / B+ 树（`m = 257`） | `4` |

## 六、常见易错点

1. **阶 `m` 与最小度 `t` 混用**：`m = 2t`。`m` 阶 B 树关键字上限是 `m-1` 而**不是** `m`；写代码时 `2*t-1` 与 `m-1` 必须一致。
2. **忘记根结点是特例**：根只有 1 个关键字（2 个孩子）是合法的，不满足 `⌈m/2⌉-1` 下界；根的唯一孩子为空时还要把根删掉、树高减一。
3. **分裂下标取错**：满结点有 `2t-1` 个键（下标 `0 ~ 2t-2`），上移的是 `key[t-1]`，左留 `t-1` 个，右取 `t-1` 个。用 0-based 时写成 `mid = (m-1)/2` 或 `m/2` 都会错一半。
4. **删除内部结点键时直接删**：必须用前驱/后继替换再递归删除，否则孩子指针无处安放。
5. **借位时绕过父结点**：直接把兄弟的键搬到欠账结点会破坏大小关系。正确做法是「父结点的分隔键下移、兄弟的边界键上移到父结点」的旋转。
6. **B+ 树内部键当成数据**：内部键只是路由用的副本，查找不能在内部结点提前返回。
7. **B+ 树删除后忘了维护索引**：删掉叶子里的键后，父结点里可能残留它的副本。多数实现选择「允许冗余」（只影响路由不影响正确性），少量实现严格同步更新 —— 这是 B+ 树删除比 B 树简单的关键，别以为漏了 bug。
8. **分裂/合并后忘记改叶子链表**：B+ 树分裂新叶必须插到 `next` 链上，且顺序为「原叶 → 新右叶 → 原后继」，插反会导致范围查询漏数据。
9. **高度公式的底数写错**：是 `⌈m/2⌉` 而不是 `m`，因为最坏情况下每个结点只用了下限个子树。
10. **把「叶结点」理解成存数据的结点**：国内教材的叶是**失败结点**（外部结点，不带信息），CLRS 的叶是**终端结点**（存关键字）。看题目先确认口径，否则层数差 1。
11. **以为 B 树适合内存**：B 树的价值在减少 I/O。纯内存场景下它的块内线性扫描比红黑树的比较更慢，`std::map` 不会用 B 树。
